> 依据：PRODUCT_VISION.md + 3.0 已落地的 Agent 体系（docs/思迹3.0版本更新方案.md）。

## 1. 现状触点清单（执行 M1 的拆除底图）

### 1.1 技能体系当前结构

- `utils/ai/skills.js`：`SKILL_REGISTRY`（7 项：memory/relation/decision/plan_phases/summary/vision/simulation，各 1-2 行通用 prompt 段）、`getSkill()`、`buildSkillsPrompt()`、`BUILTIN_AGENT_SKILLS`（仅 siji，`skillPrompts: null`）、`buildBuiltinAgentSkillsPrompt()`。
- Agent 数据字段 `skills: string[]`：`store/agent.js`（BUILTIN_SIJI.skills、createAgent 默认 `['memory']`、getAgentSkills）、`utils/agent-templates.js`（两个模板各带 skills 数组）、`store/executors/agent.js`（detail 回传 skills）。
- 注入链路：`store.getAgentSkills(activeAgentId)` → `chat-stream.js` 设 `cfg.skills/cfg.agentId/cfg.agentMode` → `chat-helpers.js` 在 system 末尾拼 `buildSkillsPrompt(cfg.skills, cfg.agentId)`。
- AI 创建：`utils/ai/tools/agent.js`（AGENT_SKILL_IDS、skillSchema、create_agent 参数 skills）、`utils/ai/prompt-actions.js` CORE_ACTIONS 文本行、`buildAgentPayload()` 白名单过滤。
- UI：`pages/settings/sub/agent_add.vue`（skill-grid 勾选区 + view-skills）、`pages/settings/sub/agent.vue`（agent-skills emoji 行）、`components/chat/MessageBubble.vue`（create_agent 确认卡技能名摘要，import SKILL_REGISTRY）。

### 1.2 删除后信息损失核对（逐技能）

技能段与现有提示词高度重叠，唯一需要补偿的三处：

| 技能段 | 现状作用 | 已有等价物 | 处置 |
|--------|----------|-----------|------|
| memory | 偏好→smart_update_profile | BEHAVIOR_RULES 自定义属性规则 + agent-loop toolInstruction | 直接删 |
| relation | 新人物→create_relation / 互动→log_interaction | BEHAVIOR_RULES[8] + agent-loop toolInstruction | 直接删 |
| decision | create_decision + 「机会成本-风险-时机」框架 | schema 在 CORE_ACTIONS/extActions，框架句缺失 | 删段 + CORE_ACTIONS 决策注释补框架句 |
| plan_phases | 大目标→create_plan_phases（2-6 阶段） | schema 在 CORE_ACTIONS，时机引导缺失 | 删段 + CORE_ACTIONS 计划注释补「大目标用 phases」 |
| summary | 周报/月报→summarize_diaries 时机 | schema 在 CORE_ACTIONS，时机引导缺失 | 删段 + agent-loop toolInstruction 补一句 |
| vision | 发图→先识别再处理 | chat-helpers 图片识别模式段（cfg.image 注入） | 直接删 |
| simulation | 模拟→start_simulation | start_simulation 不在 TOOL_DEFINITIONS，本就由模拟页驱动 | 直接删 |

结论：删除后 Agent 行为不缩水；三处提示词补偿是唯一附带改动。

## 3. M2 开场引导 Starter（P0）

### 3.1 目标
切换/创建 Agent 后，输入区上方出现 3 条示例 chips，点一下即发送。用户只做「说话、点确认」。

### 3.2 数据
- Agent 新增可选字段 `starts: string[]`：3 条以内、每条 ≤ 20 字。
- 模板预置（`utils/agent-templates.js`）：
  - 心理咨询师：「最近总提不起劲，帮我理理」「我好像又在逃避一件事」「看看我这几周的情绪记录」
  - 情感顾问：「复盘一下我和 XX 最近的关系」「帮我起草一条回复消息」「这段关系我该设什么边界」
- 思迹助手（siji）：内置固定 3 条（「记一笔最近的账单」「帮我写今天的记录」「把我想法拆成下一步」），不随会话变化。

### 3.3 create_agent 升级（与 M1 同批改 schema）
- 参数：`{name, description?, systemPrompt, starts?, icon?}`，`starts` 为 array（≤3、每项 ≤20 字），工具描述要求「一次生成 3 条贴合用途的开场示例」。
- `buildAgentPayload` 校验：数组化、截断、超 3 条截前 3；缺失不报错（UI 无 chips 兜底，不阻塞创建）。
- CORE_ACTIONS 文本行同步（新创建类参数双注册口径）。

### 3.4 UI 与交互
- 载体：`pages/chat/index.vue`，输入区与消息列表之间插入一条 chips 行（复用 welcome-chip 视觉，白底黑边圆角）。
- 逻辑：watch `activeAgentId` 与当前会话切换 → 显示当前 Agent 的 `starts`；用户发送任意消息、切换会话、切换 Agent 后重置显示；切回原 Agent 再次显示。本地 ref 状态，不持久化。
- Agent 详情 view 模式（agent_add.vue）展示 starts，供用户了解可让 AI 怎么开场。

### 3.5 验收口径
新建或切到带 starts 的 Agent → chips 出现 → 点任意一条正常发送且行内发送后隐藏 → 切走再切回重新出现。存量无 starts 的自定义 Agent 不显示、无报错。

## 4. M3 会话 Agent 绑定与恢复（P1，可选）

### 4.1 数据
- 会话结构新增可选 `agentId` / `agentName`：`createConversation()` 写入当前 Agent；存量会话无字段 → 按「未知」处理，不迁移。
- `store/chat` 切换会话时不做任何自动切换 Agent（避免多 Agent 并行浏览时来回跳）。

### 4.2 UI
- 打开历史会话时，若会话 `agentId` 存在且 ≠ 当前 `activeAgentId`：聊天页导航标题下方出现一条 pill：「该会话由 X 进行 · 切换」；点「切换」→ `setActiveAgent(agentId)` 并消失；点会话内任意发送后也消失（一次性提示，不重复打扰）。
- 会话列表项不加重标识（保持列表干净）。

### 4.3 验收口径
心理咨询师会话 A、思迹助手会话 B：A 中打开 B → 提示条出现且不自动跳；点切换后回到 B 的 Agent 并正常对话；再回 A 重复出现。
