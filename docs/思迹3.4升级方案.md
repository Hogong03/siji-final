# 思迹 3.4 升级方案 v2（慢恢复：长期、无压力、慢慢回到有状态）

> 依据：PRODUCT_VISION.md（第 0 节服务对象 + 铁律 1/4 + 3.4 新增铁律 7-9）+ 思迹 3.3 落地状态（v3.3.0 / 3300，32 文件 346 用例）。
> 用户决策（2026-09-07，针对「长期没有压力、帮自己慢慢恢复状态活力」的诉求，A/B 拍板）：四模块全做（D1=A）；能量模式纯对话推断、零用户输入（D2=A）；微光本由 AI 主动捡、只收集不评判、每日一条同日覆盖（D3=A）；3.4 整版发布，四模块一次落地（D4=A）。

> **v1 → v2 口径**：全文按 D1-D4 拍板执行。M1 不加任何状态入口/开关；M2 不建独立「微光」日记类型，用轻量 `siji_glimmers` 存储 + 功能页入口；M3 冷藏是「标记」不是新状态，冻结字段 `frozen_at`；M4 只重写复盘文案与画像缺口提醒，不动历史版本功能。

## 0. 版本定位

| 版本 | 范围 | 优先级 |
|------|------|--------|
| 3.4.0 | M1 能量模式 + M2 微光本 + M3 计划冷藏 + M4 周复盘重写 | 本次全部 |

执行原则（三条新铁律，已写入 PRODUCT_VISION.md 第 6 节）：
1. 静止是合法状态：一整天什么都没做，AI 不追问、不暗示、不惋惜。
2. 压力来自期待不来自记录：未完成信息只有用户主动问才出现。
3. 弹性默认：任一计划可一键「冷藏」，冷藏期 AI 不提，恢复原样回来。

纯本地、零推送、零评分。依赖模型能力的部分（AI 主动捡微光）用工具描述 + 行为准则约束，不依赖模型记忆。

## 2. M1 能量模式（纯对话推断，零输入）

### 2.1 目标
AI 从最近对话推断用户能量档位；低能量时自动降载：回复更短更软、不抛新话题、计划建议收敛为「只做 1 分钟」或「先放一放」。

### 2.2 落地拆解
- 新建 `utils/energy-context.js`（纯本地启发式，可单测，不依赖模型）：
  - `inferEnergyLevel(texts)`：取最近 <=6 条用户消息做关键词档位判断（极低/低/中/高），带简单否定处理（「不累/没太累」不算低能量），积极词可抵消轻度低能量。
  - `energyScan(userMessage, history)`：返回 `{ level, text }`，仅低/极低时 `text` 为注入指令，中/高返回空字符串（零 token 成本）。
- `utils/ai/chat-helpers.js` buildChatMessages：profile 等上下文之后注入能量段；低/极低能量时同时抑制 3.3 逃避点破模板（`buildPlanContext(msg, { noNudge: true })`），避免在用户耗竭时施加压力。
- 注入内容口径（写死在代码，经回归断言）：
  - 低：「回复更短更软 1-3 句；不主动抛新话题/新任务/多选建议；用户要建议只给一个 1 分钟最小选项并允许「不做也行」；聊到计划可提「先放一放也行，不会丢」」。
  - 极低：「回复 1-2 句最轻语气；不追问、不建议、不引导；不制造任何「应该做点什么」的氛围」。

### 2.3 验收
- 单测：低能量句触发注入、否定句不触发、积极句抵消轻度低落、极低 < 低 < 中。
- 手工：App 内发「今天好累，什么都不想动」→ AI 回复 1-2 句且不抛新话题/任务。

## 3. M2 微光本（每天一件「还行的小事」，允许空）

### 3.1 目标
AI 从聊天中主动捡拾用户分享的积极小事并落库（只收集、不评判、不追问）；用户随时可回看积攒的微光。每日至多一条，同日覆盖，可留空。

### 3.2 落地拆解
- 新建 `utils/storage/glimmer.js`：key `siji_glimmers`，记录 `{ id: date, date: 'YYYY-MM-DD', content, created_at }`（date 即主键，同日 upsert 覆盖）；导出 get/save/remove/count。
- 新建 `utils/ai/tools/glimmer.js` + `store/executors/glimmer.js`，注册：
  - `create_glimmer {content, date?}`（创建类，CORE_ACTIONS + TOOL_DEFINITIONS 双注册；AI 主动捡拾入口）
  - `query_glimmers {days?}`（只读，QUERY_TOOLS；默认近 30 天）
  - `delete_glimmer {date}`（仅 CORE_ACTIONS，AI 不主动删；页面可删）
- `utils/ai/prompt-actions.js`：CORE_ACTIONS 加「微光本」段；BEHAVIOR_RULES 追加一条「用户分享今天发生的小事（散步/晒太阳/按时吃饭/早睡/完成一件小事等，语气不低落）→ 可调用 create_glimmer 收进微光本，只记录不评价；用户说别记则除外」。
- 执行链路：agent-loop 工具路径走 `store.executeAction`（写操作确认闸门复用，自动执行开关开启时直接落库）；JSON 兜底路径走同一 ACTION_MAP。
- UI：`pages/settings/sub/glimmer.vue` 子页（微光列表，按日期倒序 + 单条删除 + 顶部说明「AI 会在对话里替你收着」）；功能页 AI 面板加「微光本」入口（SijiIcon sun）。
- 结果卡适配：TOOL_LABELS / MessageBubble 配色与 actionSummary / ExecResultCard 通用展示，避免未知类型空白。

### 3.3 验收
- 单测：同日覆盖、删除、倒序、空列表。
- 手工：对话「今天出门晒了会儿太阳，还行」→ AI 调 create_glimmer（自动执行开）或出确认卡；功能页 → AI 面板 → 微光本可见当天条目。

## 4. M3 计划冷藏（先放一放）

### 4.1 目标
任一计划可一键「冷藏」；冷藏期冻结执行摘要、plan_count、逃避检测与点破，AI 不主动提；解冻后原样恢复（status/executions/进度一律不动）。

### 4.2 落地拆解
- 数据：计划记录新增 `frozen_at`（时间戳或 null）。`utils/storage/plan.js` 新增 `setPlanFrozen(clientId, frozen)`；冷藏不改 status、不写 executions、不 bump updated_at（不算规划事件）。
- AI 入口：`update_plan` 支持 `frozen: true/false`（CORE_ACTIONS 与 `utils/ai/tools/plan.js` schema 同步加字段 + 注释「先放一放/冷藏 = true；恢复 = false」）；`store/executors/plan.js` execUpdatePlan 把 `p.frozen` 翻译为 `frozen_at`，且不计入结构性 plan_count、不弹「新增子计划」文案。
- UI 入口：`pages/plan/detail.vue` 底部栏加「先放一放 / 恢复计划」按钮（点击即切，不弹确认，可逆）；`form` 加 frozen_at 展示位；保存沿用 savePlan 合并逻辑（frozen_at 天然保留）。
- 列表标识：`pages/plan/components/PlanCard.vue` 加「冷藏中」角标 + 轻微降透明度；看板与列表分组仍按原 status，冷藏仅作标识。
- 冻结范围：
  - `utils/plan-context.js`：`findProcrastinationCandidates` 跳过 `frozen_at`；`buildPlanContext` 不注入冷藏计划的执行摘要/点破模板（支持 `noNudge` 选项供 M1 使用）。
  - `utils/ai/prompt-builder.js` getUserProfile：进行中计划统计排除 `frozen_at`。

### 4.3 验收
- 单测：冷藏计划不进逃避候选；冷藏不累计 plan_count；frozen_at 置空恢复后计划原样。
- 手工：详情页点「先放一放」→ 返回列表见「冷藏中」；对话点该计划名 → AI 不点破；点「恢复计划」→ 原状态回来。

## 5. M4 周复盘重写（去评价化）

### 5.1 目标
删掉一切评分句式；复盘输出 = 「这周/这次做了 N 件小事」+ 不带评价的观察 + 结尾「已经很好了」。

### 5.2 落地拆解
- `pages/plan/composables/usePlanAI.js` generateReview 提示词重写：移除「完成质量评估（优/良/中/差）」与「改进建议」，改为：
  1. 数一数实际完成的小步（引用子计划/执行记录数量，无则不编）
  2. 不带评价地描述过程与卡点（只陈述发生了什么）
  3. 结束语固定为「已经很好了」
- `utils/ai/prompt-builder.js` getUserProfile 洞察段：删除 `diaries.length === 0 → '本月还未写记录'` 缺口提醒（铁律 8：未完成信息只有用户主动问才出现）；保留正反馈类洞察。

### 5.3 验收
- 手工：已完成计划点「进度复盘」→ 输出无优/良/中/差、无「你应该」句式，末尾含「已经很好了」。
- 回归：对话首条消息不再被画像注入「本月还未写记录」。

## 7. 明确不做 / 风险

| 事项 | 状态 | 依据 |
|------|------|------|
| 能量状态入口/开关/手动标注 | 不做 | D2=A：纯对话推断，零输入负担 |
| 能量状态持久化与时间线 | 不做 | 避免 scope creep；保持启发式无状态 |
| 微光本的打卡/连续天数/成就 | 不做 | 铁律 1：任何「应该更努力」机制都是 bug |
| 微光本手动补录表单 | 本轮不做 | 记录入口统一在对话（铁律 6）；页面只读 + 删除 |
| AI 主动发起的点破/推送 | 维持 3.3 口径 | 只做「用户点名时的温和点破」 |
| 向量语义检索 | 维持现状 | 季度复盘再评估 |
| 风险：M1 启发式误判 | 只影响「语气降载」，不影响功能正确性；宁可少降不可多降（积极词抵消 + 否定处理） | 回归断言覆盖 |
| 风险：M2 AI 不主动捡 | 工具描述 + BEHAVIOR_RULES 双约束；即使不捡也不报错 | —— |
| 风险：冷藏后用户遗忘 | 恢复入口 = 列表「冷藏中」标识 + 详情按钮 + 对话可让 AI 恢复 | —— |

## 9. 一句话结论

3.4 把思迹从「把想变成 5 分钟的第一步」升级为「允许停下来」：M1 让 AI 在你没电时安静下来，M2 让「今天还行的小事」被收住而不是被追问，M3 让每个计划都能体面地先放一放，M4 让复盘不再打分——全部纯本地、零输入负担、零推送。
