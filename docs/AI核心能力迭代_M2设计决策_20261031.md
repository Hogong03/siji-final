## 0. 两个决策（已确认）

| 决策 | 结论 |
|---|---|
| 确认卡位置 | **对话内联**。确认与执行分离：内联卡负责"要不要记"，执行卡负责"已确认的事项怎么推进" |
| 容量上限 | **200 条**，配合分级淘汰；`open` 永不自动淘汰，满额触发容量保护 |

## 1. 数据模型（定稿）

存储键 `siji_open_loops`，单数组，软删除。

```js
{
  id: 'loop_<ts>_<rand>',
  kind: 'idea' | 'topic' | 'plan' | 'commitment',
  title: string,              // ≤30 字，用户可改
  status: 'open' | 'paused' | 'done' | 'dropped',
  evidence: [                 // 原话，最多 5 条，超出丢最旧
    { quote, conversation_id, at }
  ],
  first_at: number,
  last_at: number,
  touches: number,            // 被提到几次（≥1）
  next_hint: string,          // 上次停在哪，可为空
  plan_id: string,            // 转成计划后挂链
  is_deleted: 0 | 1
}
```

**kind 判定口径**（本地规则，确定性，可单测）：

| kind | 触发 | 例子 |
|---|---|---|
| `commitment` | 含"回头/下次/明天/这周"+"我" | "回头我把环境搭一下" |
| `plan` | 含明确动作 + 时间但无截止日 | "这周找时间跑一遍 RAG" |
| `topic` | 名词性主题 + 反复提及 | "RAG 那个事" |
| `idea` | 默认 | "最近又想学一下 Python" |

**与计划的边界**：有截止日 / 要打卡 / 有子任务 → 计划；只有主题、没有"做完"的判定 → 开放事项。**"我想学 X" 一律不建计划**。

---

## 2. 写入流程（必须确认，禁止静默）

```
用户消息
  → 本地 8 类句式初筛（不调模型）
  → 命中 → 生成候选 { title, kind, evidence }
  → 对话内联卡：「记成一件悬着的事？」[记下来] [改一下] [不用了]
  → 记下来 / 改完 → 落库（去重合并）
  → 不用了 → 不落库，只累加拒绝计数（用于误提取率）
```

**为什么 M2 不用模型抽取**：模型抽取要真实 Key、结果不稳定、单测只能靠语料跑批；本地规则虽然标题质量一般，但确定、零成本、可回归，且用户能"改一下"。若真实使用中误提取率 >40%，M2.5 再切模型抽取（那时已有确认卡这个安全网）。

**去重**：`title` 归一化（去标点/空格、转小写）后相同，或一条包含另一条且长度差 ≤6 字 → 合并：`touches++`、`last_at` 更新、`evidence` 追加（上限 5）。

## 3. 容量与淘汰（纯函数，单测覆盖）

`LOOP_MAX = 200`。新增时按以下顺序腾位，**每一步都只能淘汰非 open**：

1. `is_deleted=1` 的残留（真删，不进统计）
2. `status='dropped'`，按 `last_at` 从旧到新
3. `status='done'`，按 `last_at` 从旧到新
4. `status='paused'`，按 `last_at` 从旧到新
5. 仍满（200 条全是 open / 混合但无可淘汰）→ **拒绝新增**，返回 `{ ok:false, reason:'capacity' }`

> 顺序于 2026-10-31 批准为 `dropped → done → paused`：dropped 已经放弃；done 已结束、历史价值低；paused 是用户主动保留的意图，最不该丢。

拒绝时 UI 给一句事实陈述 + 一个出口（"先整理几条，或把不急的标成暂停"），**不自动丢弃任何 open 条目**。容量保护只在"确有非 open 可淘汰"时静默进行；每次淘汰写 `siji_loop_evict_log`（环形 50 条：id / 标题 / 状态 / 原 last_at / 淘汰时间 / reason），可追溯具体条目，不打扰用户。

## 4. 读取与接入

| 入口 | 行为 |
|---|---|
| M1 情境包 `pending` | 取 `status='open'` 按 `last_at` 倒序前 3 条，渲染一行：`悬着：RAG 练习（9 天）· 作品集整理（3 天）`；`very_low` 能量时整行隐去（与计划/人脉同口径） |
| 工具 `query_open_loops` | 只读，进 `QUERY_TOOLS`；支持 `status` / `kind` / `keyword` |
| 工具 `update_open_loop` | 改状态/标题/next_hint；**只进 CORE_ACTIONS，不给 Agent 自动执行**；删除类走确认 |
| 计划联动 | 用户明确说"帮我排成计划"时 `create_plan`，成功后回写 `plan_id`；反向不自动 |

## 5. 验收标准（硬门槛）

| 项 | 标准 | 验证方式 |
|---|---|---|
| 不擅自转待办 | "我想学 X" 20 条语料 **0 条**生成计划 | 单测 + AI 语料 |
| 提取准确 | 20 条标注语料，误提取 ≤20%（≥16 正确） | 新单测夹具 |
| 确认必经 | 任何写入前必须有一次确认动作，无静默写入 | 代码路径 + 单测 |
| 合并正确 | 同一件事说 3 次 → 1 条 loop，`touches=3`，`evidence` 3 条 | 单测 |
| 容量安全 | 200 条 open 时新增被拒，**0 条数据丢失** | 单测（构造 200 条） |
| 淘汰顺序 | 只淘汰 dropped → done → paused，按 last_at 旧到新 | 单测矩阵 |
| 注入 | pending 最多 3 条，一行；very_low 不出现 | context-pack 测试 |
| 成本 | 提取零模型调用；注入 ≤60 字 | 请求体实测 |
| 回归 | 全量测试绿；M1 情境包行为不变（pending 从空变有数据属预期） | 全量 |

## 9. 实施口径（2026-10-31 按批准补充，已落地）

1. **去重**：归一化相同 → 合并；包含关系只有多出来的是通用后缀（项目/计划/练习/一下/这件事…）才合并；其余保留两条（"学 Python" vs "学 Python 爬虫" 不合并）。
2. **8 类句式**：R1 想法、R2 延后承诺、R3 时间意向、R4 未完成、R5 持续关注、R6 暂停、R7 重启、R8 反复提及。R6/R7 只对已存在事项生效（不新建）；R8 不弹卡，由合并累加 `touches`。
3. **状态机**：open→paused/done/dropped；paused→open/done/dropped；done→open；dropped→open。无时间驱动变化。
4. **幂等**：`idem = 会话:规则:标题`；同一 idem 重复确认只算一次；带新标题重提则更新原条标题，不新建。
5. **next_hint**：只从「卡在/停在/做到/还剩/主要卡在」后取 2~20 字，缺失即空串。
6. **淘汰顺序（已并入第 3 节）**：`dropped → done → paused`，理由：paused 是用户主动保留的意图，比已完成的记录更不该丢。`open` 依然永不淘汰。淘汰写 `siji_loop_evict_log`（环形 50 条）。
