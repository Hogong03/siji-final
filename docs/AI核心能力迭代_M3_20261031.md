## 2. 三来源候选

| 来源 | 生成方式 | 是否独立产出 |
|---|---|---|
| 15 条规则 | `collectAdvice` 原样取，包成候选并补 `evidence.ref`（如 `snapshot.plans.overdue`） | 是 |
| Open Loops | `status=open` + 悬置 ≥3 天 + 未挂 `plan_id` | 是 |
| 用户画像 | 只参与 `fitScore`（方向贴合 0.3 权重） | **否**（有测试断言 `source==='goal'` 不存在） |

评分：`紧急度×0.5 + 方向贴合×0.3 + 新鲜度×0.2`；无画像时贴合恒为 0.5，不惩罚。

## 3. 五层过滤与独立测试

| 层 | 规则 | 测试 |
|---|---|---|
| ① 依据 | 无 `evidence.ref` 直接丢 | `没有 evidence.ref 的直接丢` |
| ② 去重 | 同域留分最高；跨域标题相似按 M2 保守口径 | `同域只留分最高的一条` |
| ③ 冷却 | 曝光 7 天 / 拒绝 14 天 / 忽略 3 次 30 天 | `冷却期内的候选不出现` + 反馈段 3 例 |
| ④ 时机 | `very_low` 不弹；`low` 只 1 条非任务 | `极低能量…` / `低能量…` 2 例 |
| ⑤ 节制 | 正常 2~3 条；不足 2 条不弹 | `不足下限 → 不弹（不凑数）` |

**2 条是展示下限，不是推荐配额**：只有 1 条 → 返回 `not-enough`、面板不弹；绝不为了凑数把下一档候选拉进来。`low` 档是唯一例外（0~1 条，且只留非任务项）。

## 4. evidence.ref 可追溯性

- 规则候选：ref 是 snapshot 字段路径，端到端测试逐条解析 `snapshot.*` 路径，确认字段存在。
- 循环候选：ref 是 `loop:<id>`，测试反查 loops 数组。
- 面板里每条方向有「看依据」，展开显示 `evidence.text` 与 `ref`。
- 端到端断言：`built.directions` 每条的 ref 都能解析（`ref 全部可解析`）。

## 5. 冷却与反馈

| 动作 | 冷却 | 说明 |
|---|---|---|
| 曝光 | 7 天 | 面板弹出时按 id 记一次 |
| 忽略 | 累计 3 次后 30 天 | 与拒绝分开计数 |
| 拒绝 | 14 天 | 用户明确点「不相关」（当前从 UI 走「不再自动弹出」+ 后续细化到单条） |
| 接受 | 不影响冷却 | 单独计数，用于接受率 |

三态分开存储（`siji_advice_seen`），`getAdviceStats()` 直接给 `shown/accepted/ignored/rejected`。

## 6. 沉默度量与统计口径

| 指标 | 口径 | 来源 |
|---|---|---|
| 拦截率 | `silence[reason] ÷ (silence 总数 + 弹出次数)` | `siji_advice_silence` 按原因分组 |
| 沉默原因 | `not-enough` / `no-candidate` / `low-no-gentle` / `energy-very-low` | `pickForPanel` 的 `reason` |
| 各层丢弃数 | `considered / available / droppedNoRef / droppedDup / droppedCooldown` | `directionsStats` |
| 拒绝率 | `rejected ÷ shown` | `getAdviceStats()` |
| 接受率 | `accepted ÷ shown` | 同上 |

注意口径边界：拒绝率低不等于质量高——样本量小、展示少都会拉低；M3.5 评估时必须同时看接受率、忽略率与样本量（与你的判断一致）。
另：沉默按「每次进入聊天页」记一次，不是按天；同一天多次进出会放大分母，看比例时以 `silence ÷ (silence + 弹出数)` 为准，不看绝对次数。
