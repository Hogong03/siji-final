# 思迹 3.2 升级方案 v2（说得准、找得回）

> 依据：`docs/思迹产品规划问答纪要_20260906.md` 第 4 节（3.2.0 范围）+ `PRODUCT_VISION.md` + 3.1 落地状态（v3.1.0 / 3100）。
> 用户决策（2026-09-06）：3.2 主题「说得准、找得回」；模型保持 DeepSeek V4 Flash 主力，新能力必须在其能力边界内设计；纯本地、无服务端。

> **v1 → v2 范围解读（2026-09-06 决策已拍板，见第 8 节 D1-D5）**：D2 把 v1 3.2 改动清单中 `findStaleAdoptedMemories()` 的口径从「删除候选」收紧为「隐藏候选」——已整合超期记忆仅从默认视图隐藏（标记 `hidden: true`），永不自动删除；涉及该函数的所有行文同步改为「隐藏」。其余 v1 文件级清单与 v2 完全一致，仅此一处语义变更 + 决策记录 + 执行顺序确认（M1 → M2 → M3 → M4）。

| 版本 | 范围 | 优先级 |

## 2. M1 纠错回归集与话语拆解精修（P0）

### 2.1 目标

把「用户体感 AI 纠错/拆解差」从玄学变成可回归的工程问题：先固化历史错误场景，跑红 → 定位是提示词、schema 还是解析层 → 修复 → 全绿。

### 2.2 新增 `tests/correction-regression.test.js`

| # | 场景（历史反馈） | 断言目标 | 断言内容（示例） |
|---|------------------|----------|------------------|
| 1 | 计划变更变成新增 | `prompt-actions.js` BEHAVIOR_RULES | 含「query_plan 找到原计划后 update_plan，禁止 create_plan 新建同名计划」 |
| 2 | 计划变更 | `agent-loop.js` toolInstruction | 含「不知道 ID 先 query_plan」类引导句 |
| 3 | 自定义属性不新增/不更改 | CORE_ACTIONS + `tools/profile.js` schema | smart_update_profile 的 updates items required = card/field/value；schema 描述含「只更新用户本次提到的字段」 |

### 2.3 话语拆解精修（按回归结果决定是否采纳）

回归集跑完后，若红项集中在「AI 漏拆」，按顺序修：
1. `utils/ai/prompt-actions.js`：CORE_ACTIONS 个人信息行补一句「一句话既含事实又含指令 → 拆成 smart_update_profile/update_profile + 对应 create_* 两个 action 一次执行」。
2. `utils/ai/agent-loop.js` toolInstruction：补「同一句含多个意图时一次发起多个工具调用，禁止只处理第一个」。
3. `utils/ai/tools/profile.js` smart_update_profile 描述补「值发生变更（不是 X 是 Y）时传新值覆盖，禁止新增一条重复属性」。

> 顺序约束：先建用例（跑出基线），再改 1-3；不允许先改后测。

### 2.4 验收口径

1. `tests/correction-regression.test.js` 全绿，任一规则句被误删时测试变红。
2. 真机用 DeepSeek V4 Flash 复述 5 条历史翻车对话（自定义属性、计划变更、错别字、多意图、纠错），修正率不低于修复前基线。

## 3. M2 记忆治理（P0）

### 3.1 职责边界（先立规矩再改代码）

| 内容类型 | 唯一权威源 | 其他层处理 |
|----------|-----------|-----------|
| 静态事实/偏好（MBTI、忌口、作息） | 我的信息画像 `siji_my_profile` | 扁平记忆只作采纳缓冲：采纳后降权并最终清理 |
| 事件/经历（带时间） | 记录 `diary_YYYY-MM` | 结构化 events 仅存「重要日期提醒」级实体 |
| 对话上下文 | 会话历史 `siji_conversations` | 不落记忆层（M3 检索兜底） |
| 需要 AI 主动引用的实体（人物/关系/重要日期） | `siji_structured_memory` | 与画像同事实时以画像为准，结构化仅存引用关系 |

### 3.4 验收口径

1. 治理弹层在「1 条记忆也没有 / 全部已整合 / 有重复」三种数据下都不报错。
2. 治理只做用户确认后的操作；无任何自动静默删除。已整合超期记忆仅隐藏（`hidden: true`），可在「已整合」分段查看并恢复，永不自动删除（D2）。
3. `buildMemoryContext` 注入文本在治理后明显变短且不再出现「画像里已有的同一句话」。

## 4. M3 旧话检索（P1）

### 4.1 目标

用户说「上次我说过 XX」「我是不是说过要戒 XX」→ AI 检索全部历史会话，回复原文摘录 + 会话标题 + 时间，不再让用户翻会话列表。

### 4.2 方案选型

A）内存遍历会话（推荐）：会话全量已在内存/单键存储，总量受裁剪上限约束（500 条/会话），本地遍历 + 简单打分足够快、零维护成本。
B）为会话建倒排索引：与 `siji_index` 同构但需增量维护，现阶段过度设计。

选 A。语义向量检索按纪要 Q5 维持现状，不做。

### 4.3 代码改动清单

| 文件 | 改动 |
|------|------|
| `utils/chat-search.js`（新增） | `searchConversations(keyword, { tag?, limit = 5 })`：读 `siji_conversations`，标题命中权重 > 用户消息内容命中 > AI 回复命中；返回 `[{ convId, convTitle, updatedAt, dateText, snippet, role }]`，snippet 截取命中处前后 20 字；无结果返回 `[]` |
| `utils/ai/tools/chat.js`（新增） | `CONVERSATION_TOOLS = [{ name: 'query_conversations', description: '检索历史会话。用户问「上次/之前/以前说过、提过什么」「是不是说过 XX」时调用。可带标签缩小范围。', parameters: { keyword: string 必填, tag?: string } }]` |
| `utils/ai/tools/index.js` | import 并展开 CONVERSATION_TOOLS；`QUERY_TOOLS.add('query_conversations')`；TOOL_LABELS 增加 `query_conversations: '检索会话'` |
| `utils/ai/tools/executor.js` | 仿 query_tags 直调分支：`query_conversations` → `searchConversations(...)` 格式化 `• 9月3日「新对话2」：…snippet…`，detail 返回 hits |
| `utils/ai/agent-loop.js` | `TOOL_RESULT_TRUNCATE_MAP` 增加 `query_conversations: 1500`；toolInstruction 补「用户问之前/上次说过什么时调 query_conversations，命中多条按时间倒序简述并注明会话标题」 |
| `utils/ai/prompt-actions.js` | CORE_ACTIONS 新增「会话记忆」段：`query_conversations: {keyword, tag?}` + 触发说明（查询类双注册口径） |
| `utils/ai/chat-stream.js` | `looksDataQuery` 正则补 `(?:是不是|有没有|可曾)(?:说过|提过)` 句式（当前只覆盖「上次/之前…说」） |

> 双注册口径：query_conversations 是只读查询，TOOL_DEFINITIONS + CORE_ACTIONS 两处都加（`action-schema-consistency.test.js` 自动校验名字集合）。不进 `store/data.js` ACTION_MAP（JSON 兜底路径不承担跨会话检索；数据类指令必走 Agent 工具循环，4 厂商均 supportsToolCalling）。

### 4.4 测试改动

- 新增 `tests/chat-search.test.js`：种子写入两条会话（标题/内容/标签不同）→ 关键词命中与排序、标签过滤、snippet 含关键词、无结果返回空、空关键词返回空。
- `tests/agent-tools.test.js` 补：`query_conversations` 在 TOOL_DEFINITIONS 且参数 required=['keyword']；QUERY_TOOLS 含它；CORE_ACTIONS 含该行。

### 4.5 验收口径

1. 说「我上次说要戒什么来着」→ AI 给出原话摘录与来源会话标题（不要求跳转）。
2. 会话标签过滤生效；检索对 20+ 会话体量无明显卡顿（H5 与真机各验一次）。
3. 存量会话（无 schema 变更）直接可检，无需迁移。

## 5. M4 计划轻量时间分布预览（P1）

### 5.1 目标

主计划详情页内，一行只读时间刻度条：把主计划区间与各子计划起止映射到均匀刻度上，节点一目了然；无滑动、无缩放、无点击跳转、默认低高度（≈48rpx）。同时收敛「时间板块占空间太大」的历史问题。

### 5.2 代码改动清单

| 文件 | 改动 |
|------|------|
| `utils/plan-time.js`（新增） | 纯函数 `buildTimeStrip(plan, childPlans, todayStr)`：收集主计划 start/end + 子计划 start/end，有效日期节点 < 2 时返回 null；否则返回 `{ start, end, totalDays, nodes: [{ id, label, kind: 'start'\|'end'\|'child'\|'today', offsetPct }] }`；跨年/长跨度（>730 天）线性压缩但首尾标签保留 |
| `components/plan/PlanTimeStrip.vue`（新增） | 只读渲染：一条 4rpx 灰线 + 实心圆点（主计划端点为黑点、子计划为灰点、今天为空心圈）+ 首尾日期小字（如「9月6日」「12月31日」）；纯黑白灰，无事件绑定 |
| `pages/plan/detail.vue` | 时间安排区改为折叠形态：头部一行 = `PlanTimeStrip` + 「编辑时间」小按钮；默认收起，点按钮才展开 `PlanTimeSection.vue` 完整编辑控件（一次解决占空间问题）；无任何日期时显示「未设置时间」灰字 |
| `pages/plan/detail.scss` | 折叠/展开状态样式 + 深色模式覆盖 |

> 不做：管理页列表内嵌预览、手势缩放、拖动节点改时间（与已删时间轴教训一致；`buildTimeStrip` 纯函数保留复用空间给未来 3.3+ 管理页总览）。

### 5.3 测试改动

- 新增 `tests/plan-time.test.js`：少于 2 个日期返回 null；主计划无日期但子计划成对 → 以子计划区间渲染；同日起止边界；跨年 offset 计算；今天在区间外不渲染 today 节点；超长跨度不产生越界百分比。

### 5.4 验收口径

1. 有时间的主计划详情页顶部见一行刻度条，不遮挡、不可交互。
2. 「编辑时间」展开/收起流畅；深色模式可读。
3. 旧计划（只有 deadline 无 start）不报错，按单点渲染或隐藏。

## 7. 不做清单（3.2 明确排除）

| 候选 | 排除理由 |
