# 后台保活方案（4.35.2）

> 一句话：Android 上做**前台服务 + 常驻通知**，让思迹退后台、从最近任务划掉后进程尽量不被回收；
> iOS / H5 / 小程序无对应能力，本方案只在 Android 生效，其余端全部静默降级。

---

## 1. 它能做到什么，做不到什么

| 场景 | 4.35.0 之前 | 4.35.0 之后 |
|---|---|---|
| 退到后台（进程还在） | 60s 轮询继续，到点 toast + 通知 | 同左，但**进程不容易被系统回收**（前台服务优先级） |
| 从最近任务划掉 | JS 全死，只能靠 4.22.0 本地推送到点弹通知 | 服务 `stopWithTask=false` + `START_STICKY`，进程大概率存活、轮询继续；被杀也仍有本地推送 |
| 划掉后 7 天没打开 App | 推送窗口滚不动，提醒断 | 同左（**这条没解决**，要解只能上服务端定时任务） |
| iOS | 无 | **无**（iOS 不允许，只能 APNs 远程推送，需要服务端） |
| H5 / 微信小程序 | 无 | **无**（浏览器/小程序没有常驻概念） |

**明确的边界**：

- 前台服务提高存活率，但**不保证**国产 ROM（MIUI / EMUI / ColorOS）在「电池优化未豁免 / 自启动关闭」时不杀。用户侧设置只能引导，不能替用户改。
- 服务本身**不持 wake lock**，不跑循环，只维持前台状态 —— 耗电影响接近 0（代价是通知栏常驻一条）。
- 常驻通知是用户可见的副作用，所以开关**默认关**，必须用户自己打开（设置 → 提示与提醒 → 后台常驻）。

## 2. 交付物

| 文件 | 作用 |
|---|---|
| `native/keepalive/src/main/java/com/siji/keepalive/SijiKeepAliveService.java` | 前台服务实现（单文件，含 running 标志） |
| `native/keepalive/src/main/java/com/siji/keepalive/SijiKeepAliveModule.java` | **原生模块入口**（4.35.2）：`@UniJSMethod` 的 start/stop/isRunning |
| `native/keepalive/src/main/AndroidManifest.xml` | service 声明 + `foregroundServiceType=specialUse` + 三个权限 |
| `native/keepalive/stubs/`（6 个文件） | **编译期 stub**：DCloud 运行时类（UniModule/WXModule/AbsSDKInstance/UniJSMethod/UniJSCallback/fastjson）的同 FQN 占位 —— 只进 javac classpath，**绝不进 aar** |
| `nativeplugins/siji-keepalive/package.json` | 本地原生插件描述（`integrateType: aar` + 一个 module 条目） |
| `nativeplugins/siji-keepalive/android/siji-keepalive.aar` | 构建产物（5.6 KB）：`classes.jar`（模块类+服务类）+ `AndroidManifest.xml` |
| `scripts/build-keepalive-aar.ps1` | 一条命令出 AAR（stub 编译 → javac → 泄漏闸门 → jar → zip → 复核） |
| `utils/keepalive.js` | JS 侧：开关、探测、双路径启停、电池优化引导 |
| `pages/settings/sub/notify.vue` | 「后台运行」组（App 端） |

**为什么有模块类 + stub 两样东西**（4.35.2 的关键转折）：

- 4.35.0 首版只有纯 Service，`package.json` 的 `plugins` 写了空数组 —— HBuilderX 打包直接拒绝：「_dp_nativeplugin.android.plugins 节点下存在为空的对象」。校验器源码（`plugins/uniapp-extension/out/index.js`）的硬性要求：**plugins 非空，每条必须有 type(module|component)/name/class**。
- 所以必须有模块类。而写 UniModule 正常要 `uniapp-v8-release.aar`（DCloud 离线 SDK，几百 MB 下载 + 版本要配对）——本方案不下载它：**模块类引用的 6 个 DCloud/fastjson 类全部从本机 HBuilderX 标准基座（`plugins/launcher/base/android_base.apk`）的 dex 里逐字节读出精确签名**，按签名写同 FQN 的 stub 参与编译。字节码只记名字：superclass 是 `io/dcloud/feature/uniapp/common/UniModule`、`getfield mUniSDKInstance:Lio/dcloud/feature/uniapp/AbsSDKInstance;` —— 运行时这些都由基座运行时的真类提供。
- **最容易踩的坑（实证）**：`mUniSDKInstance` 声明在 `com.taobao.weex.common.WXModule` 上，类型是 **`AbsSDKInstance`（接口）**，不是教程里常见的 `UniSDKInstance`。字段解析按「名字+描述符」匹配，写错类型运行时直接 `NoSuchFieldError`。`getContext()` 直接声明在 `AbsSDKInstance` 上，所以模块代码不需要任何向下转型。
- stub 泄漏进 aar 会和基座同名类冲突（打包即炸），所以构建脚本有泄漏闸门：插件 classes 里出现 `com/siji/keepalive` 之外的类，构建终止。

## 4. 打包装到手机

1. `manifest.json` 已注册插件（`app-plus.nativePlugins.siji-keepalive`）与权限（`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_SPECIAL_USE`）。
2. HBuilderX → 发行 → **制作自定义基座**（或云打包），在「App 原生插件配置」里勾选本地插件 `nativeplugins/siji-keepalive`。
3. 基座/APK 出来后装上，进「设置 → 提示与提醒」，「后台运行」组若显示开关可点 = 插件已进包；显示「当前安装包不支持」= 没进包（`utils/keepalive.js` 的 `isKeepAliveSupported` 探测的就是 `SijiKeepAliveService` 类加载）。

**4.35.0 的「空 plugins」问题已解决**（4.35.2 补上模块类后校验通过）。真机首验还剩两件事（登记在 `docs/真机验证清单.md` 2.23）：

1. 打包产物里 `uni.requireNativePlugin('siji-keepalive')` 能取到模块、start 后常驻通知出现（模块路径是正路；万一模块桥异常，JS 自动落 plus.android 反射兜底，开关不失效）。
2. 常驻通知小图标用应用图标，各 ROM 的显示效果（可能被系统裁成灰块 —— 通知小图标规范上是单色图，真机效果确认后再决定要不要出专用图标）。

兜底仍然成立：若最终放弃本地插件路线，可改走离线打包（aar 放 `libs/`、manifest 手抄）或插件市场现成保活插件（零编译，第三方质量不可控）。

## 5. 运行时行为

```
App 启动（appReady）/ 回前台（onShow）
   → utils/keepalive.js syncKeepAlive()
       开关 siji_keepalive_enabled 关 → 确保不留残服务（模块 stop / 反射 stopService）
       开关开 + Service 类在包里 → 双路径启动（同一个 Service）：
         正路：uni.requireNativePlugin('siji-keepalive').start({title, text})
               → SijiKeepAliveModule：mUniSDKInstance.getContext() + startForegroundService
         兜底：模块桥同步抛错时 → plus.android 反射构造 Intent → startForegroundService
               （正路探测只在类探测通过后进行 —— 标准基座里连 requireNativePlugin 都不碰）
                         → Service 起常驻通知（渠道 siji_keepalive，IMPORTANCE_LOW，不响不震）
                         → 点通知：getLaunchIntentForPackage(packageName) 回 App（不硬编码宿主 Activity）
   → 系统回收进程 → START_STICKY 由系统重启（intent 为 null 时用默认文案）
   → 用户划掉最近任务 → stopWithTask=false，服务不被一起停
```

**Android 版本分叉**（都在 `SijiKeepAliveService` 里判断）：

| SDK | 行为 |
|---|---|
| 21–25 | `startService` + `startForeground(id, n)`（通知渠道不存在，无需 channel） |
| 26–33 | `startForegroundService` + 渠道 + `startForeground(id, n)` |
| 34+ | 上面 + `startForeground(id, n, FOREGROUND_SERVICE_TYPE_SPECIAL_USE)`（不传类型会抛 `MissingForegroundServiceTypeException`） |

`startForeground` 抛异常（通知权限被拒/渠道被删）时服务直接 `stopSelf()`，**不会崩溃循环**。

## 6. 服务类型的取舍（为什么是 specialUse）

| 类型 | 结果 |
|---|---|
| `dataSync` | Android 15 起有 **6 小时/24 小时**运行上限，超时系统强停 —— 对「一直挂着」的场景等于自废 |
| `specialUse`（已采用） | 无时限；但需要在 manifest 写 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` 说明用途，**Google Play 审核要理由**，国内商店无此要求 |
| `shortService` | 只能跑 ~3 分钟，不适用 |

要改类型：`native/keepalive/src/main/AndroidManifest.xml` 的 `android:foregroundServiceType` + `SijiKeepAliveService.startAsForeground()` 里传给 `startForeground` 的常量，两处必须同时改，然后重跑构建脚本。

## 7. 排查

```powershell
adb shell dumpsys activity services com.HBuilder.UniApp   # 或实际包名；应有 SijiKeepAliveService, isForeground=true
adb logcat -s SijiKeepAlive:*                              # 服务自身日志极少，主要用于确认拉起
```

进程被杀后没重启：先看是否被 ROM 冻结（电池优化白名单 + 自启动），再看 `START_STICKY` 是否被 `stopSelf` 打断（通知权限被拒时会发生）。
