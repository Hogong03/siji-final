## 三之十一、4.8.4 后「isDark is not defined」运行时报错排查定案（2026-10-02）

**用户报**：切深色页面被背景全覆盖；console 报 isDark is not defined（render function）。

**排查（13+3 项，全部实测）**：

- CSS 管线：dart-sass → @vue/compiler-sfc 全链模拟，:global 产物干净无属性注入（scripts/_pipeline_probe.cjs）
- 无头 Chrome 渲染探针：theme-dark 下 chat DOM 可见、elementFromPoint 无覆盖层（scripts/_overlay_probe.html）
- compileScript(inlineTemplate) 全量 84 个 vue：无任何组件运行时引用未定义 isDark（scripts/_isdark_probe.cjs）
- store 调用差集：全项目 35 个 store.X 全部有聚合层导出
- uni-h5 官方包源码核对：setNavigationBarColor/setTabBarItem 行为与守卫一致
- 用户侧探针：全屏 fixed 层数 0、点击点直接是 HTML.theme-dark —— **页面内容整个没渲染，不是被盖住**

**定案**：源码全干净 + 运行时却报旧错误 = **dev 进程内存里的旧模块图**。HMR 只做增量替换，
F5 刷新与清磁盘缓存都不会重建它； uni-agent 与本会话在 4.8.2-4.9.1 期间高频改动文件，
浏览器内存里混杂了多个版本的组件渲染函数。唯一解法：**HBuilderX 完全停止运行进程 → 重新运行**
（不是 F5）。磁盘缓存（unpackage/dist/cache、node_modules/.vite）已清。

**本轮防御性清理**：App.vue 摘除 page.theme-dark（选择器组整组作废风险，commit d717937）。

## 三之九、4.8.4 scoped 穿透总根因修复（2026-10-02）

**用户报**：决策页/计划页仍白；外观切浅色不变；功能页滑块不变色；图标颜色不变。

**总根因（compileStyle 实验铁证）**：scoped 样式里的 `.theme-dark { .foo{} }` 编译成 `.theme-dark[data-v-x] .foo[data-v-x]` —— 属性选择器挂在 .theme-dark **自身**，而类挂在 html 根（无 data-v 属性）→ **4.8.0 以来所有 scoped 内的类驱动深色块整体从未生效过**（用户看到的一直是 4.7.x media 版系统跟随的旧产物）。四症状全部归此：决策/计划页白、滑块不变、图标不变、切浅无感。

**修法（实验选型）**：`:global(html.theme-dark) { … }` 编译后为干净祖先链 `html.theme-dark`，无属性注入。scripts/_scoped_fix.py 全量替换 93 处（幂等），App.vue 全局样式不动。

**守卫升级**：theme-mode 守卫测试新增裸 .theme-dark 禁止断言 + :global 形态配对断言，防回归。

**教训**：vue scoped 官方规则「属性加在最后一个选择器」在祖先引用场景必踩坑；祖先类驱动的主题方案必须 :global 穿透或全局样式表。此坑 4.8.0-4.8.3 四个版本都没发现，因为「测试全绿」≠「样式真的命中」—— 静态检查与单测都不做浏览器渲染。

**并行情况**：uni-agent 已提交它的 4.8.2（`280a46f`，AI 链路 20 项），本轮发版顺延用 4.8.4；工作区另有其 4.9.0 进行中半成品（ai-enhance-490.test.js 有 1 失败，与本项目无关未动）。

## 五、为什么上一轮的压缩会失败（根因）

压缩不是本地做的，是**远端 compact 服务**跑的一次调用。那条线程的失败记录给了两条硬错误：

```
Error running remote compact task: {"error":{"message":"The supported API model names are
deepseek-flash, deepseek-v4-pro, but you passed glm-5.3-flash.", ...}}

Error running remote compact task: Fatal error: remote compaction v2 expected exactly one
compaction output item, got 0 from 2 output items
```

结论：**远端压缩只接受 deepseek 系模型**，那条线程跑的是 `glm-5.3-flash` → 直接 `invalid_request_error`；换成 deepseek 之后又撞上第二个错（压缩输出项数量不符，0 个）。两次都是 harness 侧的问题，不是项目代码的问题，**在对话内部改不动**。

能做的：① 出问题就用 deepseek 系的线程；② 靠这个检查点文件兜底 —— 上下文没了但结论还在。
