# 思迹 AI 核心能力迭代：源码审查、差距分析与技术方案

> 输入：《思迹（SIJI）AI 核心能力迭代需求交接》（2026-10-31）
> 版本基线：4.50.0 / 4490（工作区，124 文件 1746 用例）
> 本文只做审查与方案，不改代码。所有"现状"结论都有文件与行号依据；所有"成本"都是增量，不是总量。

---

## 0. 结论先行

1. **三项 P0 里，只有"主动思考"有现成骨架。** `utils/advice.js` 已经做完"取数 → 归一 → 规则 → 门控 → 面板"的整条链路（签名去重、每天 2 次上限、4 条让位规则、900ms 延迟）。它缺的不是机制，是"方向"这个数据结构和"AI 合成"这一层。
2. **"理解能力"没有独立层，它散在 10 个上下文块里。** 每次请求由 `buildChatMessages` 现场拼 10 段上下文，每段自己判关键词、自己决定要不要注入。这不是"理解能力弱"，是**没有一个地方能回答"这一轮 AI 到底知道什么"**。所以不要新建"AI 大脑"，要加一个**情境包（Context Packet）聚合层**。
3. **"持续跟进"是真空。** 现在只有"计划"（有日期、有状态机）和"记忆"（无状态的一句话），中间那层"提过但没定、定了但没做、做了但没收尾"完全没有载体。这是本轮唯一必须新建存储的模块。
4. **方案总量：4 个模块，5 个阶段，10~13 个工作日。** 新增每轮上下文 +300~500 token（现有注入的 2%~4%），主动分析每天 1 次模型调用（约 1.2k token）。不引入向量库、不引入服务端、不动 P1 冻结的五态。

## 1. 现有实现盘点（每一条都可核对）

### 1.1 注入链：一次请求到底拼了什么

`utils/ai/chat-helpers.js` L54-135 是唯一入口。按拼接顺序：

| # | 块 | 触发条件 | 预算 | 代码位置 |
|---|---|---|---|---|
| 1 | system 静态段 + 扩展 action | 总是 | 模块级缓存，120s TTL | `prompt-builder.js` L214-294 |
| 2 | 用户近期数据（月度/近3月/近期记录/账单/洞察） | 总是 | 无硬上限 | `prompt-builder.js` L122-198 |
| 3 | 画像摘要 | 画像 `enabled=true` | 600 字硬预算 | `profileContext.js` L86-125 |
| 4 | 长期记忆 | 开关开 | top-30 条 | `memory/context.js` L21-76 |
| 5 | 关系上下文 | 命中关系词或人名 | 无 | `relations.js` |
| 6 | 关系回溯 | 命中回溯意图 | 无 | `relation-traceback.js` |
| 7 | 决策上下文 | 命中决策词 | 无 | `decisions.js` |
| 8 | 能量感知 | 开关开 + 判出低能量 | 一段指令 | `energy-context.js` |
| 9 | 计划上下文 | 命中计划词且点名计划 | 无 | `plan-context.js` |
| 10 | 动静摘要 | 开关开，且非 very_low | 无 | `progress-digest.js` |

**问题不在块多，在于三件事：**

- **没有统一出口**：想加一条"AI 应该知道的事"，必须改 `chat-helpers.js` 再改一个领域文件，且顺序固定（越早注入离用户消息越远，模型注意力越弱）。
- **预算只有一处**：除画像 600 字外，其余块无上限。记忆 30 条 + 关系 + 回溯 + 摘要叠起来轻松过 3k 字。
- **门控是关键词表**：`CONTEXT_KEYWORDS`（L45-50）只有 4 组正则。说"最近又想学一下 Python"命中不了任何一组——它既不是关系词、也不是计划词。这正是需求里那个例子的现状。

### 1.2 检索链：记忆怎么被找出来

- `memory-rank.js`：CJK 二元组 + ASCII 词 → BM25（k1=1.2）+ 同义/拼音扩展（字面 1.0 / 全拼 0.75 / 首字母 0.65 / 同义 0.6）+ 45 天半衰时间衰减 + 类目权重（fact/preference 1.25、summary 0.85）。
- `selectMemories`：有命中取 top-30；无命中回落最近 30 条；**query 少于 4 字直接返回空**（L157-160，防寒暄扛全量记忆）。
- `memory-structured.js`：实体/关系/事件三元组，query 里出现实体名（字符串包含）就把它排到最前。
- 旧话检索：`query_conversations` / `query_diary` 是**工具**，由模型自己决定调不调。

**能力边界**：检索只对"当前这一句话"生效。没有"最近反复出现的话题"这种跨会话聚合；实体命中要求名字完全一致（"阿伟"能中，"伟哥"不能）。

### 1.3 建议链：已经做到的比需求文档假设的多

`utils/advice.js` + `advice-rules.js` + `components/advice/AdviceSheet.vue`：

- snapshot 覆盖 6 个域：计划（过期/今天/快到期/今日打卡）、账单（月笔数/总额/预算比/断档）、记录（今天/近 7 天）、人脉（久未联系）、画像（完整度）、环境（无 Key/首启/离线/深色）。
- 15 条规则，`ADVICE_LIMIT=4`，第一条非 info 的就是"现在最该做的一件事"（`pickAdviceFocus`）。
- 门控：新的一天弹一次；签名（日期|时段|环境|数据指纹）变了且距上次 ≥3 小时再弹；每天最多 2 次；首启/无 Key 卡/本轮已弹汇总表时让位；延迟 900ms 晚于汇总表。（`pages/chat/index.vue` L659-687）
- 每条建议带 `action`：跳页 / 开引导 / 预填输入框。

**它缺的三样**：① 条目是"提醒"不是"方向"（没有 why、没有第一步、没有互斥性）；② 全是静态阈值，不会说"你最近反复提到 RAG"；③ 没有依据引用，用户无法判断"它凭什么这么说"。

### 1.4 执行链与确认闸门（本轮不改，但方案必须绕开）

- Agent 最多 5 轮（`MAX_ROUNDS=5`），38 个工具，`QUERY_TOOLS` 16 个只读自动执行，`CONFIRM_TOOLS` 只有 `delete_feedback`。
- 金额 ≥500 的账单动态确认；写操作有"先查再改"铁律；`STRONG_ACTION_RE` 命中且零工具时纠偏一轮。
- 结论：**任何新的写能力都必须走"确认后才落库"**，包括本轮要做的开放事项。

### 1.5 可用的数据资产（不需要新建采集）

计划（含打卡/子计划/冷藏/到期）、记录（按月分片 + 标签）、账单（按月 + 预算）、人脉（关系 + 互动）、决策、微光、画像（卡片 + 字段）、长期记忆（flat + 结构化三元组）、对话历史（按会话存）。

**没有的**：睡眠、运动、体重、体检等身体数据。需求里"结合睡眠/加班/运动记录"这类例子在数据层不成立，方案不要围绕它设计。

## 2. 九个问题的差距矩阵

| # | 需求 | 现状 | 差距性质 | 结论 |
|---|---|---|---|---|
| 1 | 统一上下文理解机制 | 10 段注入，各管各的 | 缺聚合层 | 新建 `utils/context-pack.js`，**聚合不新建数据** |
| 2 | 区分长期目标/短期兴趣/临时情绪/焦虑想法 | 画像有「职业方向/人生关键词/当前阶段」，但无实体；记忆 category 只有 fact/preference/event/summary | 缺语义分层与载体 | 画像复用；新建开放事项 `kind` 字段承担"想法/话题/承诺" |
| 3 | 首页主动分析 | 规则引擎已存在 | 规则是静态阈值，无主题聚合 | 在 advice 上加"主题"与"AI 合成"两个数据源，机制不动 |
| 4 | 生成 2~3 个有依据建议 | 单条 item + 一个 focus | 缺"方向"结构与证据字段 | 新增 `direction` 结构 + `evidence` |
| 5 | 对话中自动关联 | 关系/回溯/决策各有门控 | 只覆盖人脉，不覆盖目标与主题 | 扩门控词典 + 常驻"长期方向"一行，**不新建检索** |
| 6 | 未解决事项持续跟进 | 无 | 完全缺失 | 新建 `open_loops` 存储 + 提取 + 查询工具 |
| 7 | 控制成本/频率/上下文长度 | 签名去重、每天 2 次、600 字画像预算 | 缺模型调用的日预算 | 沿用门控；AI 合成每天 1 次、输出上限 400 token |
| 8 | 避免重复/无依据/错误记忆 | 签名去重、ADVICE_LIMIT、记忆去重与画像过滤 | 无依据链、无误记纠正入口 | 每条方向必须带 evidence；引用可点开、可否定 |
| 9 | 可解释/可纠正/可关闭 | `features.js` 能力开关 + `prompt flag` | 建议无来源、无"这条不对" | 复用开关体系，新增来源标注与纠错动作 |

**一句话**：9 个问题里，5 个是"有零件、缺总装"，2 个是"有机制、缺数据"，2 个是真空白（开放事项、依据链）。

## 3. 模块设计

### M1 情境包 Context Packet（`utils/context-pack.js`）

**职责**：把散在 10 处的取数收敛成一份结构化对象，再渲染成一段 ≤300 字的【当前情境】。它只做归一和事实陈述，**不做判断**（判断是模型的活）。

```js
// 纯函数：取数全部可注入，便于单测
buildContextPacket({ now, deps }) -> {
  now, bucket, weekend,
  energy: 'low' | 'medium' | ...,
  facts: {
    plans:   { active, overdue, dueToday, checkedToday },
    diary:   { today, week },
    bill:    { month, budgetPct, lastDays },
    relation:{ stale, staleName },
    profile: { pct }
  },
  threads: [ { key, topic, hits, lastAt } ],   // 近 14 天高频话题（来自记录标签 + 开放事项）
  goals:   [ { text, source } ],               // 画像「职业方向/人生关键词/当前阶段」
  pending: [ { id, kind, title, days } ]       // 开放事项未闭环，最多 3 条
}
renderContextPacket(packet) -> string   // ≤300 字，纯事实，无建议
```

**关键约束**：
- 只渲染**有数据**的字段；空字段整行消失（不写"暂无"）。
- 不写任何"应该/建议/还没"的措辞，避免与铁律 1、8 冲突。
- 注入位置固定在 system 末尾（离用户消息最近）。

**复用**：`advice.js` 的 `collectSnapshot` 已经是 80% 的雏形。M1 不复制它，而是把 `collectSnapshot` 的取数抽成公共函数，advice 与 packet 共用一份——**单一事实来源**，否则两处数字必然对不上（4.29.5 汇总表踩过这个坑）。

### M2 开放事项 Open Loops（`utils/open-loops.js` + `store`）

**它解决的问题**：用户说"最近又想学 Python"，这句话既不是记录、也不是计划，但它是**一个悬着的话题**。三天后再提，AI 应该说"上次你说想系统学，后来停在环境搭建"。

**数据结构**（存储键 `siji_open_loops`，软删除 `is_deleted`）：

```js
{
  id, kind: 'idea' | 'topic' | 'plan' | 'commitment',
  title,            // ≤30 字，用户原话改写
  status: 'open' | 'paused' | 'done' | 'dropped',
  evidence: { quote, source: 'chat', conversation_id, at },  // 必须是原话
  first_at, last_at, touches,        // 被提到几次
  next_hint,        // 上次停在哪（可选，模型填）
  plan_id           // 已转成计划时挂链，避免两套并行
}
```

**写入流程（必须确认，不静默）**：
1. 对话结束后本地规则初筛 8 类句式（"我想/我打算/最近在考虑/一直想/要不要/回头/下次/还没定"）。
2. 命中则**不直接落库**，在当前回复的 `suggestions` 或执行卡里给一句"要把这个记成一件悬着的事吗"。用户点是才写（走 `CONFIRM_TOOLS` 同款闸门）。
3. 同一 `title` 模糊匹配到已有 loop → `touches++`、`last_at` 更新，不新建。

**与计划的边界（写进提示词，不靠自觉）**：
- 有截止日、要打卡、有子任务 → 计划；
- 只有主题、没有日期、没有"做完"的判定 → 开放事项；
- **"我想学 X" 默认不建计划**（愿景铁律 4 与需求"不擅自把聊天转成待办"是同一件事）。

**读取**：
- 注入：M1 的 `pending` 取最近 3 条 open，一行一条（标题 + 悬了几天）。
- 工具：`query_open_loops`（只读，进 `QUERY_TOOLS`）。
- 建议：作为 M3 的"方向"来源之一。

### M3 主动建议 v2：2~3 个方向（改 `advice.js` / `advice-rules.js` / `AdviceSheet.vue`）

**方向结构**：

```js
{
  id, title,            // ≤12 字，用户能一眼选
  why,                  // 一句依据，必须引用事实（"上周你提过 3 次 RAG"）
  firstStep,            // ≤5 分钟，可执行
  evidence,             // { source: 'loop'|'plan'|'diary'|'bill', ref, text }
  entry                 // { type:'nav'|'prefill'|'guide', ... } 复用现有 action
}
```

**三条生成路径（按优先级，命中即停）**：

| 路径 | 数据源 | 例子 | 成本 |
|---|---|---|---|
| A 事实 | 现有 15 条规则聚合成分组，同域只出一条 | 计划逾期 3 项 → "先处理最久的那件" | 0 |
| B 主题 | 开放事项 + 近 14 天记录高频标签 | "RAG 你已经悬了 9 天，今天只做环境装好" | 0 |
| C 探索 | 无任何紧急项时 | "回顾上周 / 记一句 / 随便聊聊" | 0 |
| D 合成（可选） | A+B 候选 + M1 packet，调一次模型 | 把 5 条候选收敛成 3 个互斥方向，各配一句 why | 1 次/天 |

**规则（写死，测试守）**：
- 输出 2~3 个方向，**方向之间必须不同域**（不能两条都是账单）。
- 每条必须带 `evidence`；没有 evidence 的候选直接丢弃，不进模型也不进面板。
- 用户忽略 = 不产生任何待办、不写任何状态（现有 advice 无副作用，保持）。
- 7 天内同一 `id` 不重复出现（现有签名粒度太细，需按方向 id 另存一份 seen 表）。
- 关闭开关后：0 次自动弹出、0 次模型调用（`isFeatureActive('proactive_advice')` 一处裁决）。

**AI 合成的输出契约**（严格 JSON，失败回落规则路径）：

```json
{ "directions": [
  { "id": "loop:rag", "title": "把 RAG 环境装好", "why": "你 9 天前说想系统学",
    "firstStep": "只装依赖，跑通一个 hello world", "evidenceRef": "loop_1729..." }
] }
```
`evidenceRef` 必须是输入里给过的 id，模型编造的 id 一律丢弃——这是"无依据建议"的硬闸门。

### M4 对话内关联（改 `chat-helpers.js` + 新增 `utils/goal-context.js`）

**两件事，都很小**：

1. **常驻目标行**：把画像的「职业方向 / 人生关键词 / 当前阶段」+ 最近 1 条 open loop 压成 ≤120 字，**每轮注入**。成本固定，让模型永远知道"这个人在往哪走"。
2. **关联门**：当前消息命中目标词 / 主题词 / 实体名时，注入**对应那一条**历史（不是全量记忆）。实现上扩 `CONTEXT_KEYWORDS` 为 `CONTEXT_TRIGGERS`，每类带一个 builder，返回最多 1 条。

**纠错**：AI 引用历史后，用户说"不是这个/我没说过"→ 调 `update_loop`/`delete_loop`（确认后）。这条要进提示词，否则模型只会道歉不会改数据。

**回滚**：每个模块一个开关（`features.js` 注册），关掉后行为回到 4.50.0。M2 的存储独立建键，不迁移旧数据。

## 5. 成本与风险

### 5.1 token 增量（相对现状）

| 项 | 频次 | 增量 | 说明 |
|---|---|---|---|
| M1 情境包 | 每轮 | +250~400 | 全字段都满时 300 字封顶 |
| M4 目标行 | 每轮 | +120 | 固定一行，不随数据增长 |
| M4 关联注入 | 命中时 | +150~250 | 只注入 1 条，不叠全量记忆 |
| M2 pending 3 条 | 每轮 | +60 | 有 open loop 才注入 |
| M3 AI 合成 | 每天 1 次 | 输入 ~800 + 输出 ~400 | 失败回落规则，不重试 |
| M2 提取 | 每天 ≤1 次 | 输入 ~600 + 输出 ~300 | 只在初筛命中时调 |

合计每轮 **+400~700 token**（现有注入的 3%~6%）；每天固定新增 **≤2 次小调用**。按 30 轮/天算，月增量约 0.4~0.6M token，费用取决于所选厂商单价（当前默认组合下不到 1 元/月量级）。**成本不是风险，重复建议才是。**

### 5.2 风险表

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 建议变成新的"每日任务推送" | 方向每天换着说法说同一件事 | 方向 id 级 7 天去重；同域只出一条；忽略不追问 |
| 错误关联（"我没说过这个"） | 记忆/loop 的 evidence 与原话不符 | evidence 必须存原话；引用可点开；否认即改/删 |
| 想法被擅自转成待办 | 模型把"我想学 X"建成计划 | 提示词硬约束 + 语料断言 + `create_plan` 前后置校验（loop 未确认不得建计划） |
| 上下文膨胀 | 6 个月后 threads/pending 变多 | packet 每个数组硬上限（3/3/3），超出按时间截断 |
| 多厂商行为不一致 | GLM/Kimi 不守 JSON 契约 | 合成结果只接受严格 JSON；解析失败回落规则路径，不重试 |
| 与 P1 五态冲突 | 开放事项与"待回顾"语义重叠 | loop 只管"没日期的事"；计划的事一律走 plan，两边用 plan_id 挂钩 |
| 测试负担 | 新增 3 个模块 + 语料 | 纯函数优先（packet/规则/提取都是纯函数），UI 只做渲染 |

## 6. 测试与验收

### 6.1 单测（新增，按项目惯例）

- `tests/context-pack.test.js`：空数据 → 输出空串；单域数据 → 只出现该域；全满 → ≤300 字；不出现"应该/建议"字样。

- `tests/advice-directions.test.js`：2~3 条、不同域、每条有 evidence、无 evidence 被丢、7 天去重。
- `tests/goal-context.test.js`：目标行为空 → 不注入；命中 → 只注入 1 条；否认路径调 update。

### 6.2 必跑守卫（按 AGENTS 规矩）

`action-schema-consistency` + `module-exports` + `ai-eval*` 三件套；动了 `features.js` 要跑开关相关；新增工具要同时进 `CORE_ACTIONS` 与 `TOOL_DEFINITIONS`（查询类）并登记 `QUERY_TOOLS`。

### 6.3 AI 语料（`utils/ai/eval/cases.js`，新增 6 条）

1. "最近又想学一下 Python" → 关联到长期方向，反问"系统学还是解决具体问题"，**不建计划**。
2. "我想学 RAG，但今天不想学" → 只接住 + 5 分钟一步，不催、不新建待办。
3. 3 天后再提 RAG → 带出上次进度（loop 的 next_hint）。
4. 用户否认关联（"我没说过"）→ 不道歉式敷衍，改/删数据。
5. 无数据时打开应用 → 2~3 条探索方向，不编造"你最近很焦虑"。
6. 有逾期计划 + 悬置话题 → 两条方向不同域，各带依据。

### 6.4 验收口径（可量化，写进版本日志）

- 打开应用 3 秒内出 2~3 个方向，每条可展开看依据；关闭开关后 0 次自动弹、0 次模型调用。
- "想法不转待办"：20 条语料 0 误建计划。
- 跨会话衔接："3 天后再提"≥8/10 能带出上次进度。
- 误关联率：20 条反例（无目标、无主题、纯情绪）注入层 0 误触发。
- 每轮上下文增量 ≤700 token（抓请求体实测，不估算）。

### 6.5 人验

- H5：三套脚本（空数据 / 有一周数据 / 有 3 个 loop），浅深色各一遍，390×844。
- 真机：新增 1 节到 `docs/真机验证清单.md`（面板滑出、方向卡点击、来源展开、忽略后不再弹）。
- **H5 通过不等于 App 通过**，面板类组件必须真机复验（4.10 起的既有教训）。

## 8. 需要拍板的五个问题

1. **首页建议以规则为主还是 AI 为主？** 建议：规则出候选、AI 只做收敛（D 路径默认开）。全 AI 生成的话，四条厂商模型契约不一致，回落路径会变成主路径。
2. **开放事项允许静默写入吗？** 建议：不允许。必须一次确认，否则"我没让你记这个"会把信任打掉。
3. **方向数量 2 还是 3？** 建议：3，窄屏折成 2+1 滚动；下限 2，不足 2 条就不弹（宁缺毋滥）。
4. **是否复用 P1 的"待回顾"？** 建议：不复用。P1 是计划的收尾态，开放事项是"还没有计划的事"，语义不同，共用会让状态机变脏。
5. **AI 合成每天几次？** 建议：1 次。第二次打开应用只刷新规则路径，不再调模型。
