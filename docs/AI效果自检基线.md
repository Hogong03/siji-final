# AI 效果自检基线

> 用法
> - 每次跑完自检（设置 → 关于 → AI 效果自检），在「记录」表里登记一行；改过提示词 / 工具 / 确认逻辑后必须重跑并登记
> - 读法：**通过** 是「模型自己选对了工具与顺序」；**靠兜底**（页面 `~`）是「模型没调工具，前端正则把结果救回来」——后者结果虽对，但不能算 AI 会拆解
> - 报告头部自带「自检口径」与「应用版本」；口径版本变化代表度量语义变了，跨口径的数字不可直接比

---

## 1. 三档口径

| 符号 | 含义 | 是否算通过 |
|---|---|---|
| ✓ | 模型调对了工具（顺序、参数、确认闸门都对） | 是 |
| ~ | 模型没调工具，靠前端兜底执行（结果会落库） | 否 —— 这是「AI 拆解能力差」的证据 |
| × | 未通过（工具选错 / 该调没调 / 参数错） | 否 |
| – | 跳过（缺数据前置，如没有可改的计划或账单） | 不计入分母 |
| ! | 请求出错（网络 / Key / 模型侧） | 否 |

**通过率 = 通过 ÷（总数 − 跳过）**。跳过不进分母：没跑过的用例不该拉低数字。

## 3. 覆盖率边界（别把全绿读成「AI 没问题」）

- 语料 23 条，全部来自历史反馈的真实原话，覆盖：计划变更 / 打卡 / 自定义属性 / 错别字 / 口头时间 / 多意图 / 大额确认 / 纠错 / 网址粘连 / 闲聊不写。
- **没有覆盖**：多轮上下文里的指代（「那个计划」）、图片与文件输入、关系与决策类、跨轮纠错（上一轮记错、下一轮改）、方言与口语长句。
- 通过 ≠ 落库结果正确：自检测的是「选了哪个工具、参数对不对」，落库字段正确性由 `tests/executors.test.js` 那一层负责。
- 全绿后的价值是**回归**：任何改动提示词 / 工具 / 确认逻辑之后重跑，掉下来的那几条就是被改坏的。

---

## 4. 扩语料的规矩

1. 只收**真实原话**（来自开发者反馈导出），不自己编。
2. 涉及「已存在的计划 / 某一笔账单」的，一律用 `{plan}` / `{billAmount}` 占位符并声明 `needs`，别写死名字 —— 写死会让用例在数据变化后假失败（3.7.1 的 4 条失败就是这么来的）。
3. 只写能判定的断言（工具名、顺序、参数、确认闸门、回复必含/禁含），别断言模型的措辞。
4. 相对日期现算（`dayStr`），不写死日期。
5. 加完跑 `tests/ai-eval.test.js`（语料结构校验会拦住缺 expect / id 重复）。
