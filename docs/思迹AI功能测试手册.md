## 3. 执行流程

1. 清缓存重编译，确认版本 2.3.3
2. 按 P0 -> P1 -> P2 顺序执行；每个用例独立成行记录结果
3. 异常用例（03 章）建议最后统一执行，便于区分环境问题与产品问题
4. 发现失败：记录 设备/模型/复现步骤/实际表现/应用日志，用开发者反馈导出

## 4. 通用判定标准

- 通过：行为与预期一致，无重复内容、无“走神/超时”假象掩盖真实错误
- 失败：功能不可用、回复重复、崩溃、错误提示与真实原因不符
- 阻塞：环境/Key 缺失导致无法执行（记录后跳过）
- 所有 AI 回复须验证：loading 正常结束、无残留光标、历史记录保存后重进会话内容一致

目的：验证失败场景下错误真实可见、降级可用、不崩溃。建议在真机上执行（App 分块流式链路）。
日志观察：HBuilderX 控制台 `[ChunkedStream]` / `[Stream]` / `[Stream Retry]` 前缀。

## 1. 配置类异常

| 编号 | 场景 | 操作步骤 | 预期结果 |
|---|---|---|---|
| TC-040 | 未配置 Key | 清空当前厂商 Key 后发送消息 | 提示先配置 Key；不走离线假回复；不崩溃 |

| TC-044 | 图片被模型拒绝 | 视觉模型返回 400（如格式不支持） | 显示真实错误原因；不静默降级成“走神” |

## 2. 网络与限流

| 编号 | 场景 | 操作步骤 | 预期结果 |
|---|---|---|---|

## 4. 降级与恢复

| 编号 | 场景 | 操作步骤 | 预期结果 |
|---|---|---|---|
| TC-054 | 失败后重试按钮 | 触发一次失败 | 失败气泡带重试入口；点击后重新发送同一条消息 |
| TC-055 | 失败回复不入记忆 | 触发一次失败后问“还记得我刚才说什么吗” | 失败内容不被提取进记忆/画像 |
| TC-056 | 切会话回写 | 流式生成中切换到其他会话 | 原会话保留已生成内容；无 loading 残留 |

## 5. 重点检查

- 任何失败场景不得出现“抱歉，我刚才走神了”这种无信息量提示（2.3.2 已改为真实错误）
- 回复不得整段重复（2.3.3 已加去重，重发场景在真机多测几轮）
- 失败后应用不崩溃、不白屏、会话数据不丢失

## 4. 已知注意事项

- 通义语音转写走公网 URL 模式，App 客户端不直传音频
