## 3. 探针方法与范围

**做法**：新建临时 vitest 用例，mock `uni` 存储（复用 `tests/setup.js`），直接调生产函数 `buildChatMessages` / `buildAdvice` / `buildProfileContextBrief`，打印注入结果与建议条目。不联网、不调模型、不写真实数据。

**能测的**：注入链（模型能看到什么）、建议引擎（面板给什么）、纯函数行为。
**不能测的**：模型最终怎么回（需要真实 Key，且会烧 token）。这类指标留给 M2/M3 的 AI 语料跑批。

**为什么不用 `dryRun` 跑真实会话**：`dryRun` 只拦写操作、查询仍走真实链路，需要已配置的 Key 与真实数据；当前仓库里没有可用凭据，强行跑会得到一堆网络错误而不是行为基线。改成"注入层探针"能拿到同样有效的结构性证据，且零成本、可复现。

## 4. 实测结果

| 编号 | 场景 | 关键数字 | 结论 |
|---|---|---|---|
| P1 | 空库 +「最近又想学一下 Python」 | system **6650 字**，0 个目标/方向块 | 模型只能靠猜 |
| P2 | 有画像（职业方向=AI 工程）+ 2 条记忆，同一句 | system **6848 字**（+198），记忆里确实有 RAG | 信息在，但**没有任何"要关联"的指令**（正则匹配为 false） |
| P3 | 「我想学 RAG，但今天不想学」 | 能量段 **未触发**；open_loops 存储 **不存在** | 情绪降载没接住这类表达；想法无处存放 |
| P4 | 三天后「上次说的 RAG 从哪开始」 | 含 RAG=true（靠兜底），含"上次/进度"=**false** | 能捡到词，接不上进度 |
| P5 | 有计划（2 逾期 + 1 今天到期）+ 账单 | 3 条建议**全在计划域**；字段只有 `key,tone,title,desc,action` | 没有"方向"，也没有依据 |
| P6 | 同一批数据连开两次 | 签名稳定；条目**无 id** | 只能整表去重，做不到方向级去重 |
| P7 | 空画像 + 3 条旧记忆，「今天天气不错」 | 旧记忆注入 **3/3** | 无关消息也会扛全部记忆，是错误关联的原料 |
| P8 | 画像 14 个长字段 | 577 字 / 保留 14 / 丢弃 0 | 600 字预算生效（**不是缺陷**，记录为已验证能力） |
| P9 | 空库首页建议 | 只有 **1 条** `start-empty` | 按"不足 2 条不弹"的新规则，新用户将永远看不到面板 |

**P5 的重复缺陷**（现场抓到）：`plan-today`（今天有 1 项到期）与 `plan-soon`（最近的还有 0 天）指向**同一项计划**，同一次面板里说了两遍。

**P1→P2 的 198 字**是这次最重要的数字：画像 4 个字段 + 2 条记忆，只占 system 的 2.9%。剩下的全是 action schema、铁律、表达规范。M1 的价值就是用同一块预算，把"关于你"的比例抬上去。

## 6. 三个观察指标的定义（先把尺子立起来）

| 指标 | 定义 | 采集点 | 当前值 |
|---|---|---|---|
| 跨会话关联准确率 | 触发了关联的轮次里，引用内容被用户接受（未否认、未纠正）的比例 | 关联注入时打点 `siji_probe_link`（M4 落） | 未测 |
| 错误建议率 | 展示的方向里，被用户点开"依据"后标记"不对/不相关"的比例 | 建议卡负反馈（M3 落） | 未测 |
| 开放事项误提取率 | 初筛命中并弹出确认，但用户拒绝的比例 | 确认卡拒绝计数（M2 落） | 未测 |

三条都要求"用户动作"作为真值，不接受模型自评。**没有真值之前，任何"准确率提升"的说法都不成立。**

M1 的前置约束（写进实现，别临场决定）：

1. M1 只做**聚合与渲染**，不新增存储、不改任何领域取数口径。
2. `collectSnapshot` 抽公共函数时，advice 的现有输出必须逐条不变（回归用快照断言锁住）。
3. 情境包必须能在"零数据"下返回空串，且不出现"应该/建议/还没"这类词。
4. 新注入位置固定在 system 末尾，且整段 ≤300 字。
