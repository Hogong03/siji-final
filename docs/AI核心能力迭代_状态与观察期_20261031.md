## 3. 指标口径（定稿）

| 指标 | 公式 | 粒度 |
|---|---|---|
| 接受率 | `accepted ÷ shown` | 按方向 id 计次 |
| 忽略率 | `ignored ÷ shown` | 同上 |
| 拒绝率 | `rejected ÷ shown` | 同上 |
| 沉默率 | `silence ÷ (silence + 自动弹出数)` | **每次页面挂载**计一次（见下） |

三个已知口径细节（都会影响读数，先写明）：

1. **「进入聊天页」= 页面挂载**：`maybeShowAdvice` 只在 `onMounted` 调用，切 tab 回来不重复。所以一天多次进出只按一次算，沉默率不会因反复进出被放大。
2. **手动打开面板不计入「自动弹出数」**：从计划速览面板点「看看建议」属于用户主动索取，不该算作「系统本来要说话」。当前实现里手动打开会给方向记 `shown`（用于冷却），但**没有区分自动/手动**——这是缺口，见 §4。
3. **沉默只在「够格但没内容」时记**：开关关闭、签名未变、当天已满 2 次这些情况直接 return，不记沉默。也就是说沉默率回答的是「该说话了，但说不出来」，不是「系统今天没打扰你」。

## 4. 当前测量缺口（不修就拿不到两周后的数据）

### 缺口 1：忽略与拒绝没有采集点

- 用户关掉面板（点遮罩/关闭）→ 什么都没记，「忽略」永远是 0。
- 「不再自动弹出」是**全局开关**：点一次之后所有自动建议（含沉默）全部停止，后续数据归零。
- 没有单条「不相关」入口，「拒绝」也永远是 0。

结论：**按现状跑两周，`ignored`/`rejected` 会接近 0，不是用户不拒绝，是没地方拒。** 届时只能看接受率和沉默率。

### 缺口 2：各层拦截数不落盘

`directionsStats` 只随 `buildAdvice` 返回，页面用完即丢。两周后无法回答「是依据层丢得多，还是冷却层丢得多」。

### 缺口 3：自动弹出数与手动打开数混在一起

`shown` 同时记录自动与手动两种来源，沉默率分母会偏大（显得系统更少沉默）。

**最小补丁建议（约 20~25 行，不改任何判断逻辑）**：
1. 关闭面板且未点击任何方向 → 对本次展示的 id 记 `ignored`。
2. 卡片脚部加一个「不相关」→ `rejected` + 从当前列表移除（不落库到别处）。
3. `markDirectionsShown(built, source)` 区分 `auto|manual`，另记一个 `autoShown` 计数，供沉默率分母使用。
4. 每次 `buildAdvice` 把 `directionsStats` 累加进 `siji_advice_diag`（同一份四个计数器 + 次数）。

这四条只加埋点，不改候选、过滤、时机、排序的任何行为。**待你批准后再动手；不批准就按现状观察，但两天后拿不到忽略/拒绝/分层数据。**

## 5. 观察期要看的五个问题

| 指标 | 回答什么 | 判读注意 |
|---|---|---|
| 接受率 | 建议是否真的有用 | 样本 <30 次不做结论 |
| 忽略率 | 是否常被无视 | 与接受率一起看 |
| 拒绝率 | 是否有明显误报 | 单看低拒绝率无意义 |
| 沉默率 | 系统太保守还是太积极 | 太高 → 候选太少或过滤太狠；太低 → 说得太勤 |
| 各层拦截数 | 哪一层过滤失效 | 需缺口 2 的补丁 |

判断顺序：先看样本量 → 再看沉默率是否落在可接受区间 → 最后才看接受/拒绝。**低拒绝率不等于质量高，可能只是几乎不给建议。**

## 6. 发布前必须补的 UI 验证（不阻塞观察期）

1. 方向卡是否一眼看懂（标题 + 一句依据 + 先做）。
2. 「看依据」展开后是否挤压阅读、长文本是否溢出。
3. 深色模式：卡片背景、依据区、按钮对比度。
4. 长标题（接近 20 字）是否截断或撑破布局。
5. 关闭面板后再次进入是否会意外重复弹出（依赖 7 天冷却与签名，需实测）。
6. 点方向卡 → 跳转/预填是否落在正确位置。

无运行环境，本轮全部未验；列为 4.51.0 发布前的硬门槛。
