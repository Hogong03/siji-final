## 0. 结论

开放事项从「提过就散」变成「可确认、可追踪、可收尾」的一条链路：说一句话 → 本地规则认出候选 → 对话内联卡确认 → 落库 → 下一轮注入「悬着：…（N 天）」→ 用户说暂停/完成/重开时改状态。

**写入的唯一入口是确认卡**，AI 两条路都拿不到新建权限。全量测试 130 文件 / 1841 通过 + 1 expected fail。

## 2. 数据模型与状态流转

存储键 `siji_open_loops`（单数组、软删除），另有 `siji_loop_stats`（展示/接受/拒绝计数）、`siji_loop_dismissed`（7 天弃用表）与 `siji_loop_evict_log`（容量淘汰日志，环形 50 条）。

```js
{ id, kind: idea|topic|plan|commitment, title(≤30), status,
  evidence: [{quote, conversation_id, at}]（≤5）, first_at, last_at,
  touches, next_hint(≤20), plan_id, idem, is_deleted }
```

**状态转换**（白名单，纯函数 `canTransition`）：

| 当前 | 允许 |
|---|---|
| open | paused / done / dropped |
| paused | open / done / dropped |
| done | open |
| dropped | open |

- 同状态调用返回「已是该状态」，不写库。
- 非法转换（如 done→paused）返回 `illegal-transition`，数据不变。
- **没有任何时间驱动的状态变化**：三天不提、一个月不提，状态仍是 open（有测试锁住）。

**与计划的边界**：`create_plan` 不会被本模块触发；`update_open_loop` 只接受 `plan_id` 关联，反向往回写不做。

## 3. 八类规则与语料

| 规则 | 触发示例（正例） | 反例 | 说明 |
|---|---|---|---|
| R1 想法 | 最近又想学一下 Python | 今天天气不错 | 输出 kind=idea |
| R2 延后承诺 | 回头我把环境搭一下 | 这周找时间跑 RAG（归 R3） | kind=commitment |
| R3 时间意向 | 这周找时间跑一遍 RAG | 明天再说吧（无动作） | kind=plan |
| R4 未完成 | 上次那个功能还没弄完 | 我完成了（无"没"） | kind=topic，可带 next_hint |
| R5 持续关注 | 最近一直在关注 AI Agent | AI Agent 是什么？ | 需"一直/最近"+关注类动词 |
| R6 暂停 | 之前那个项目先放一放 | 先放一放（无对应事项） | **只改已有事项**，不新建 |
| R7 重启 | 之前那个准备重新开始 | 重新开始（无对应事项） | 只对 paused/dropped 生效 |
| R8 反复提及 | 同一主题第二、三次出现 | 首次出现 | 不弹卡，由合并累加 `touches` |

**统一反例**（不产生候选）：问句结尾、以「什么/怎么/为什么/多少」开头、少于 4 字、纯情绪与闲聊。

**next_hint**：只从「卡在 / 停在 / 做到 / 还剩 / 主要卡在」后取 2~20 字；没有就说没有（`''`），不推断下一步。

测试语料：`tests/open-loops.test.js` 的「规则层：8 类句式」9 条 + 反例 1 组；`utils/ai/eval/cases.js` 新增 2 条（想法不转计划、查询悬着的事）。

## 4. 容量与去重结果

**去重（已按你的口径收紧）**：
- 归一化后完全相同 → 合并。
- 包含关系只有在多出来的部分是通用后缀（项目 / 计划 / 练习 / 一下 / 这件事…）时才合并。
- 其余一律保留两条：`学 Python` 与 `学 Python 爬虫` 实测 **2 条**（不误合并）。

**容量（200）**：
- 淘汰顺序：`dropped → done → paused`，各自按 `last_at` 从旧到新；`open` 永不自动淘汰。
- 200 条全 open → `{ok:false, reason:'capacity'}`，UI 提示「已满 200 条，先整理几条」，**原数据一条不动**（有测试断言数量仍为 200）。
- 有可淘汰项 → 静默腾位后新增，结果数量仍 ≤200；**每次淘汰写 `siji_loop_evict_log`**（环形 50 条，记录 id / 标题 / 状态 / 原 last_at / 淘汰时间 / reason），可追溯到具体是哪一条，而不是只知道"淘汰了几条"。

> 顺序已按 2026-10-31 验收意见确认：`dropped → done → paused`（dropped 已放弃、done 已结束、paused 是主动保留的意图）。设计文档 §3 已同步。

## 5. 确认卡：交互实测记录

**没有截图——本机没有可运行的 H5/真机环境**（`package.json` 只有测试依赖，没有 dev/build 脚本，HBuilderX 不在自动化范围内）。所以这里给的是**数据层点击序列实测**，不是视觉验收。

| 操作序列 | 预期 | 实测结果 |
|---|---|---|
| 说「最近又想学一下 Python」→ 点「记下来」 | 1 条 open | 通过（`open-loop-flow` 首例），提示「记下了」 |
| 连点两次「记下来」 | 仍 1 条 | 通过（第二次返回 `duplicate`，提示「已经记过了」） |
| 点「改一下」改成「系统学 Python」→ 确认 | 1 条，标题为改后的 | 通过 |
| 先确认，再带新标题重提同一候选 | 更新原条，不新建 | 通过（`duplicate` + 标题更新） |
| 点「不用了」 | 0 条，7 天内不再问同一标题 | 通过（`markDismissed` + `isDismissed`） |
| 同一句话再说一次（不同轮） | 合并，`touches+1`，仍 1 条 | 通过 |
| 第 4 类：「还没弄完，卡在向量库配置」 | `next_hint=向量数据库的配置` | 通过 |
| 无卡点的话 | `next_hint=''` | 通过 |

模板一致性由 `tests/sfc-bindings.test.js` 编译校验（`OpenLoopCard` 与 chat 页都过）；**视觉、深色、键盘/点按手感未验证**，见第 9 节。
