# 思迹 UI 优化方案（2026-10-05）

> 依据：4.12.x 连续发版期间的真机截图、代码走查与 DESIGN_SYSTEM.md 既有体系。
> 原则：**减法优先**——设计哲学是「AI 回复内容是唯一有视觉权重的焦点，UI 本身退让」，
> 所以优化方向以收纳噪音、统一尺度、补齐短板为主，不引入新装饰。
> 分级：P0 = 体验直接受损 / P1 = 一致性债务 / P2 = 加分项。均为可确认后执行的方案。

---

## P0-1 消息操作行收纳（聊天页最大噪音源）

**现状**：每条消息下方常驻「时间 + 复制（+编辑）」灰色按钮行——截图实测它比内容还显眼，一屏 N 条消息就有 N 行操作，违背「UI 退让」。
**方案**：气泡上只保留一个极小的时间戳（20rpx、弱灰）；「复制/编辑/重新生成」收纳进**长按气泡呼出的操作面板**——usePressHold（4.12.6 修复后）已具备可靠的位移容差与 tap 守卫，不会再重演滑动误触；呼出位置跟随按压点。用户消息与 AI 消息的可用操作不同，面板按 role 出牌。
**落点**：MessageBubble.vue（meta 行改条件渲染）+ 新操作面板组件；触点用已有 usePressHold。
**量级**：中（1 天）。

## P0-2 行内小图标按钮的热区垫高（误触的另一半根源）

**现状**：对话行「加标签/重命名」按钮 padding 只有 4-8rpx，实际触区远小于 44px 标准——「对话编辑不好用」一半来自热区太小导致的误触/漏触，与 4.12.6 的长按误触是叠加关系。
**方案**：所有行内小按钮统一**透明热区垫高**到 64×64rpx（视觉尺寸不变，用透明 padding 撑）+ `:active` 反馈。全局排查：对话行、气泡操作、计划行、记录行。
**落点**：ConversationListItem.vue、MessageBubble.vue、各列表行组件；规则写进 DESIGN_SYSTEM.md。
**量级**：半天。

## P0-3 深色模式次级文字对比度达标

**现状**：深色下消息时间戳/元信息用 #52525B（Zinc-600）压在 #18181B 上，截图实测几乎不可读；#A1A1AA 压 #27272A 也偏弱。深色不是「把浅色变暗」，次级信息也要能扫到。
**方案**：按 DESIGN_SYSTEM.md 自己的深色映射执行到位——text-hint 深色用 #71717A（而非 #52525B）、meta/时间戳统一提到 #71717A；做一次**深色对比度专项 pass**（WCAG AA：正文 ≥4.5:1，辅助 ≥3:1），逐页核对。
**落点**：各页面/组件 scss 的深色块（机械替换，风险低）；App 端编译后真机抽查。
**量级**：半天 + 真机抽查。

## P1-1 圆角与间距 token 化（一致性债务）

**现状**：圆角 8/10/12/14/24rpx 混用、间距存在硬编码；`$radius-sm` 有定义但覆盖不全。同层级的元素在不同页圆角不同，肉眼看「不齐」。
**方案**：uni.scss 补全尺度（$radius-xs 8 / sm 12 / md 16 / lg 24 / xl 32；圆角语义：按钮 sm、卡片 md、弹层 lg、气泡 24）；新代码强制 token，旧代码分批替换（每页顺手改，不做一次性全量替换以控风险）。
**落点**：uni.scss + 渐进式替换。
**量级**：制度即刻生效；替换随迭代。

## P1-2 统一空状态组件

**现状**：聊天页的恢复卡/无 Key 卡、记录/账单/计划的空列表、搜索无结果——每处各写一套图标+文案+按钮，视觉和结构都不一致。
**方案**：抽 `components/common/EmptyState.vue`（SijiIcon 大图标 + 标题 + 副文案 + 可选主按钮，深浅双主题内建），各空状态改为数据驱动调用；聊天页无 Key 卡与恢复卡的层级关系也顺手理顺（恢复卡在上，引导卡其次）。
**落点**：新组件 + 6~8 处调用点替换。
**量级**：1 天。

## P1-3 输入框 focus 态去跳变

**现状**：`input-wrap:focus-within` 在深色下把背景从 #27272A 整块切成 #18181B——点击输入瞬间底色跳变，视觉重心晃动。
**方案**：focus 反馈只用**边框高亮**（#FAFAFA 已有）+ 轻微 border 宽度变化，底色不动；浅色同理核对。
**落点**：InputArea.vue 深浅两块各删一行 background。
**量级**：10 分钟。

## P2-1 简报卡进展可视化

4.12.0 简报卡已有指标格/主按钮；下一步把「进展条目」从文本行升级为**计划联动迷你进度**（每个进行中计划一条 4rpx 进度条 + 百分比），数据 query_plan 已有，纯展示层。量级：半天。

## P2-2 统计页 hero 数字层级

bill/stats 概览区四张卡平铺；改为一主（本月支出大数字 + 环比）三辅的层级，月报长图已验证这种排版的信息效率。量级：半天。

## P2-3 App 冷启动深色闪现预注入

4.12.3 已知边界：冷启动首帧浅色闪现。方案：main.js/appReady 在 plus.webview 就绪后、首页 onLoad 前对**即将创建的首页 WebView** 预 evalJS（或启动参数带 theme 标记由页面 onShow 前置挂类）。量级：半天，需真机验证闪现消除。

## P2-4 发送后等待反馈

从发出到首 token 有 2-6 秒空窗（只有 loading 三点）；方案：loading 气泡内加一行极淡的阶段性文案轮换（「正在思考…」「正在调用工具…」——onStatus 已有工具名回调可用），让等待可感知。量级：2 小时。

---

## 执行建议

- **第一批（P0 三项 + P1-3）**：体验立刻可感、风险低，一次发版
- **第二批（P1-1/P1-2）**：一致性，随迭代分批
- **P2 按需点单**
- 所有涉及深色的改动遵守现行规矩：App 端关键视觉 JS/内联驱动，scss 块只做 H5 主实现
