# 思迹产品规划问答纪要（2026-09-06）

> 内部决策文档：内容涉及个人使用语境，禁止外发、截图外传与公开渠道（同 `PRODUCT_VISION.md` 隐私红线）。版本基线：v3.1.0（3100）。
> 问答对象：朱红庚（产品唯一用户）；问答形式：12 题 × 5 组，逐条拍板。

---

## 1. 背景与目的

把「自用验证期」的产品方向从愿景层收敛到可执行版本范围。问题设计依据：`PRODUCT_VISION.md`、`docs/思迹3.0版本更新方案.md`、`docs/思迹3.1Agent升级方案.md`、`AI技术升级方案_20260827.md`、近期版本历史与开发者反馈记录。

本次问答不新增功能清单，只做两件事：
1. 把「先自己用」阶段的边界钉死（做什么、不做什么）。
2. 为 3.2/3.3 版本范围给出排序依据。

## 3. 分组结论与影响

### A. 目标与自用验证

- 发行、上架、多设备、云同步整体后置；产品保持单机、纯本地、无账号形态。此决策同时锁定了技术架构方向：不为多用户预留，不引入服务端。
- 自用验证不设通过标准，避免把「恢复期」做成 KPI 压力源。替代方案：每次版本收尾用一份「月度自检清单」（连续使用、核心闭环无返工、AI 写入错误率可接受），主观通过即可。
- 纯本地带来的已知风险（换机/损坏丢数据）已被 Q12 显式接受，备份改造不进入近期版本。

### B. 记忆与画像

- 用户感知：3.0 起的「记忆整合进我的信息」已解决「AI 引用」的主要问题；当前痛点是整合后的**冗余与治理**（同一事实多处存放、分组混乱），以及**找不到旧记忆**（无法说「上次我说过……」并得到准确引用）。
- 影响：短期不做向量语义检索（Q5 未决 = 维持现状）。先做两件事：
  1. 记忆治理：画像/长期记忆/月结的职责再切分，「一个事实只存一处」；提供去重合并与来源标注。
  2. 旧话检索：自然语言触发（「上次/之前我说过……」）→ 关键词索引（现有 `siji_index` 平滑升级）+ AI 查询引导，不引入服务端。
- Q5 每季度复盘一次：触发再评估的条件是「关键词检索 miss 率明显影响体验」（用户抱怨找不到）。

### C. 计划模块

- 计划分层（主计划/子计划、变更即更新）在 3.1 已落地。下一步按序做：
  1. 轻量时间分布预览：吸取「时间轴占用过大 → 删除」的教训，只做**不占空间、无手势复杂度**的静态概览（如折叠卡片内一行时间刻度）。
  2. 最小行动闭环（愿景 P1）：AI 把想法收敛成「5 分钟内可做的第一步」，用户只确认一步。
- Q7 拍板「主动温和点破计划性逃避」。与铁律 1（不制造失败感）的调和是**实现约束**而非二选一：
  - 触发口径：同一计划连续 3 次「只规划不执行」。
  - 文案口径：一句事实观察（如「这个计划三周没有动过了」）+ 一个缩小/删除选项；禁止「你应该更努力」「加油」等评价与催促词。
  - 依赖：需要先有「执行记录」数据（点确认/标记完成），与最小行动闭环同批建设更顺。

### D. AI 能力优先级

- 用户排序：① 话语拆解与纠错 ② 图片/截图识别泛化。两者都已在 3.0/3.1 多次加固（BEHAVIOR_RULES、纠错主动权、vision-bridge），仍排第一说明**效果未达预期**——下一步不是继续加规则，而是先建「纠错回归集」：
  - 把历史真实错误对话（自定义属性不落库、计划变更新建、错别字误解、多意图只处理一半等）固化为 10-20 条测试用例；
  - 每次提示词/工具改动跑一遍，先定位「是提示词问题还是模型能力问题」，再决定修法。
- 模型策略（Q9）：主力 DeepSeek V4 Flash 不动，出问题再评估迁移（候选 GLM-5.3 / Kimi K3 已完成调研，迁移成本集中在 providers.js）。约束：**新能力默认必须在 V4 Flash 能力边界内设计**。
- 矛盾点（需实测）：图片识别若要求视觉模型，而主力是 DeepSeek V4 Flash → 要么识别类请求临时路由到已配置的视觉模型，要么接受识别质量边界。此项进 3.3 前先做能力验证。
- 语音输入（Q10）明确不做，近期路线不再讨论。

### E. 迭代与工程机制

- 开发者反馈闭环维持现状（App 内导出聊天记录 → 贴给 Codex），只优化导出包质量：自动附带应用版本/平台/模型/相关会话与报错上下文（3.0 起已具备，持续补强即可）。
- 备份改造（加密包/自校验/一键还原）后置，等用户实际遇到数据焦虑时再提。

## 4. 版本路线建议（3.2 → 3.3 → 候选）

### 3.2.0（近期，主题：说得准、找得回）

1. 纠错回归集 + 话语拆解精修：固化历史错误用例，按回归结果修提示词/工具 schema（承接 Q8-①）。
2. 记忆治理：画像/长期记忆职责切分、去重合并、来源标注（承接 Q4-B）。
3. 旧话检索：自然语言触发 + 关键词索引升级（承接 Q4-C）。
4. 计划轻量时间分布预览（承接 Q6-A；不占空间、无手势）。

### 3.3.0（中期，主题：把想变成 5 分钟的第一步）

1. 最小行动闭环：计划拆到 5 分钟第一步、只确认一步、执行记录落库（承接 Q6-B + 愿景 P1）。
2. 计划性逃避温和点破 v1：基于执行记录，非评判口径（承接 Q7-A）。
3. 图片/截图识别泛化：先做视觉模型能力验证，再决定 OCR/多轮截图组合的范围（承接 Q8-②）。

### 3.4.0+（候选，不承诺）

- 状态觉察与情绪识别（愿景 P2，为「语境建议切换 Agent」打底）。
- 金钱真相：自动归账 + 每周三数字播报（愿景 P3）。
- 社交能量预算 + AI 起草回复（愿景 P4）。

排序理由：3.2 全部是低风险、纯本地、不依赖模型新能力的工作；3.3 中最小行动与点破机制共享「执行记录」数据；状态觉察依赖情绪识别基础设施，排最后。

## 6. 与 PRODUCT_VISION 的关系与冲突处理

- **排序修订**：愿景第 8 节的迭代优先级（P1 最小行动 → P2 状态觉察 → P3 金钱真相 → P4 社交能量）按用户真实体感重排：纠错与记忆治理提前，状态觉察/金钱真相/社交预算后置。内容不冲突，仅顺序调整；本纪要作为愿景排期的执行修订版，编写大版本方案时引用本纪要。
- **铁律 1 × Q7-A**：点破机制必须按「非评判观察 + 可选项」实现，禁止任何评分/打卡/催促机制（见 3.3.0-2 的文案口径）。
- **隐私红线**：本地数据含情绪与个人状态信息，推广/开源前必须整体脱敏改写（沿用愿景第 0 节）。
- **单机边界**：Q2/Q3 确认愿景「先自用」阶段不设期限；架构上不为推广预留（不引入账号/云），避免增加复杂度。

## 8. 一句话结论

3.2 的主题是「说得准、找得回」：纠错回归 + 记忆治理 + 旧话检索 + 计划轻量预览；3.3 是「把想变成 5 分钟的第一步」：最小行动闭环 + 逃避温和点破 + 图片识别泛化；语音、发行、云同步明确不做。
