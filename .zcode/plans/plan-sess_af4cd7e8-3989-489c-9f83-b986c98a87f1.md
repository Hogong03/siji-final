## 思迹 v4.5.0：上班打卡 + 进入对话单消息重构

### 需求与已确认决策
1. **上班功能**：新增「上班模板」（复用计划系统：1 根计划 + 「上班打卡」「下班打卡」两个每日循环子计划）；每天上下班提醒打卡；提醒弹窗可推迟（5/15/30 分钟多档 + 默认档可配）；弹窗可直达打卡。
2. **进入对话重构**：每天进入应用的新对话**只有一条 AI 消息**，囊括 问候 + 总结 + 下一步操作 + 计划过时/快到期提示；聊天页「下一步」单卡取消（并入消息，「每天一次」语义保留）。

### 现状关键事实（已核实）
- 模板体系：`ensureDefaultTemplates` 按 client_id 增量补发（utils/storage/plan.js:93+），`createPlanFromTemplate`（store/data.js:225-309）支持 offset_days 与递归子计划；子任务支持 `recur_type: 'daily'`。
- 提醒系统缺口：`setPlanReminder` 不落盘 `repeatType`（settings.js:48-58，UI 采集了但存丢，scheduler.js:51 读不到）——循环提醒实际存不进去，本版必须修。
- 提醒无 snooze：触发即 `markTriggered` 永久防重；弹窗仅「查看/关闭」两按钮（notifier.js:34-114）。
- 打卡：`logPlanCheckIn`（storage/plan.js:281-300）一天一条（对两个子计划模型无影响）。
- 进入对话：`maybeStartFreshSession`（useChatSession.js:88-105）总结优先、欢迎语回落；下一步是聊天页独立单卡（index.vue:676-685 + useChatEngine.js offerNextStep:87-100）；下一步「每天一次」标记 `siji_next_step_shown`（next-step.js:52-58）。
- 逾期口径已有：usePlanList.js:106（status!==2 且 due_date 已过）；提醒层 isOverdue（scheduler.js:162）。

### Part 1 上班打卡（约 8 个文件）

**1.1 上班模板** — `utils/storage/plan.js`
- 新增 `tpl_work`：name「上班」，plan_data 含两个子任务 `上班打卡`/`下班打卡`（recur_type:'daily'，est_minutes:1，tags:['工作']），根计划 tags:['工作']、不设 deadline（长期）。
- **模板扩展**：plan_data / subtask 支持可选 `reminder: {enabled, customTime:'08:30'|'18:00', repeatType:'daily'}`，`createPlanFromTemplate` 创建计划后逐个调 `setPlanReminder` 写入提醒（这是模板能带提醒时间的机制）。

**1.2 修 repeatType 不落盘** — `utils/reminder/settings.js`
- `setPlanReminder` 增加 repeatType 字段的读取与持久化（cfg.repeatType 已被 scheduler.js:51 消费，只差存储）。

**1.3 snooze 能力** — 新增 `utils/reminder/snooze.js`（纯小模块）
- 存储 key `siji_reminder_snoozed`：`{[fireKey]: {planId, fireAt}}`。
- API：`snoozeReminder(fireKey, planId, minutes)` / `dueSnoozes(now)` / `clearSnooze(fireKey)`。
- `utils/reminder/settings.js` 增加 `snoozeMin`（默认 5）+ getter/setter。

**1.4 调度接入** — `utils/reminder/scheduler.js`
- `checkAllReminders`：常规命中 ∪ 到期 snooze；命中后**不再立即 markTriggered**，交给 notifier 处理结果——用户选「打卡/查看」→ `markTriggered + clearSnooze`；选「推迟」→ `snoozeReminder(fireKey, planId, minutes)`（可连续推）。未处理就关掉弹窗 → 下轮轮询重响（未标记），符合「该打没打继续催」。
- 防重复弹：同一 fireKey 弹窗打开期间不重复触发（进程内 pending 集合）。

**1.5 触发 UI 直达打卡** — `utils/reminder/notifier.js`
- App 内触发改用 `uni.showActionSheet`（三端一致，无需挂载组件，符合底部弹出习惯）：`['立即打卡', '推迟 {snoozeMin} 分钟', '推迟 15 分钟', '推迟 30 分钟', '查看计划']`（snoozeMin 与 15/30 去重）。
- 「立即打卡」→ 直接 `logPlanCheckIn(planId, 今日)` + toast「已打上班卡/下班卡」+ markTriggered；「查看计划」→ 现有跳转；后台 plus.push / H5 Notification 行为不变（点击拉起 App，进入后由轮询补弹）。
- 打卡成功可触发既有 `checkinFeedback` 里程碑回执（utils/checkin-feedback.js）。

**1.6 默认推迟档设置 UI** — `components/plan/PlanReminderSection.vue`
- 提醒编辑区加一行「推迟默认档」三选（5/15/30，写全局 `snoozeMin`，注明全局生效）；顺手把 repeatType 传参链路补完整（usePlanForm.js:59,244 → setPlanReminder）。

### Part 2 进入对话单消息重构（约 7 个文件）

**2.1 新增 `utils/plan-alerts.js`（纯函数）**
- `collectPlanAlerts(plans, now, {dueSoonDays:3})` → `{overdue:[{clientId,name,lateDays}], dueSoon:[{clientId,name,leftDays}]}`：口径 = status!==2、未删除、未冷藏/顺延；deadline 日期 < 今天 → overdue；今天 ≤ deadline ≤ 今天+3 天 → dueSoon。循环计划无 deadline 不参与。
- 新测试 `tests/plan-alerts.test.js`。

**2.2 `utils/enter-dialogue.js` 扩展（核心改动）**
- `buildEnterSummaryMessage(summary, extras)`：extras = `{alerts, nextStep, workStatus}`；正文段落顺序 = 问候 opener → 总结行（有事件才出）→ **计划状态行**（overdue：「有 N 个计划已过截止：A（3 天）、B——要收尾、顺延还是今天做掉？」；dueSoon：「「X」还有 2 天到期」）→ **下一步行**（「下一步可以从「{title}」开始，约 N 分钟。」）→ **上班卡行**（2.1.7）→ tail。
- **消息恒产出**：无事件/无提醒/无下一步时仍出「问候 + 通用按钮」的消息——`maybeStartFreshSession` 不再回落欢迎语，`buildWelcomeMessage` 使用点删除（`dropWelcomeMessages` 保留用于清理存量落盘欢迎语）。
- 签名扩展：`enterSummarySignature` 追加 `alertsTotal` 与 `nextStepId`，防止同日 away 刷新重复内容雷同消息。
- 按钮新增两类：`{kind:'next', prefill:'开始做{title}'}` 与 `{kind:'checkin', value:planId, label:'去打卡'}`；现有按钮（查看详情/看计划/看新记录/看账单/聊聊/通用三键）不动。

**2.3 `composables/useEnterSummary.js`**
- `computeSummary` 读计划表（getPlanList）：并入 `collectPlanAlerts` + 上班卡状态（按 tag「工作」+名称含「打卡」识别子计划，`satisfiedToday` 判今天是否已打）+ `pickNextStep`（`shouldOfferNextStep` 为 true 才给，给出即 `markNextStepShown`——消息给出即占用当天名额）。

**2.4 聊天页去单卡** — `pages/chat/index.vue` + `composables/useChatEngine.js`
- 删除 `.next-step-card` 模板/样式、`offerNextStep` 及其在 handleSend 收尾的调用、next-step 相关 import；`handleEnterButton` 支持 `kind:'checkin'`（`store.executeAction({type:'log_checkin',...})` + toast）与 `kind:'next'`（prefill）。
- `.resume-card`（回去接着聊/选择历史对话）保留——它是页面级空态入口，不是消息。

**2.5 兼容与判空** — `utils/chat-session.js` / `store/chat/persist.js`
- `isEmptyConversation` 已同时认 `_isWelcome`/`_isEnterSummary`，无需改；persist 白名单已含全部标记，无需改。
